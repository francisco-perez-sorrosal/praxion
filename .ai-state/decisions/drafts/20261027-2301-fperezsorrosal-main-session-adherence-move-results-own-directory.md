## Context

The kernel flip gate reads every `*.json` in `.ai-state/eval_ledger/adherence/` and requires each index row to carry a `roles` map (`scripts/kernel_run_index.py`); a results file the index does not list makes the next commit holding a switched record stale (`I9-run-index-stale`). REQ-01 and AC-01 require that recording a move run change no gate finding and no role index entry. The delta-check checkpoint of 2026-10-27 chose option (b) of SQ-13 and asked for this record. Category: the decision places data inside one component (the adherence eval) and changes no component or boundary, the flip gate's contract included, so it is `implementation`, not `architectural`.

## Decision

Move results files are written to `.ai-state/eval_ledger/adherence/moves/<run_id>.json` (`"schema": "move-results/1"`, `"subject": {"kind": "move", ...}`), and their index to `moves/index.json` (`{"schema": 1, "runs": {...}, "skipped": [...]}`), regenerated after every write and by `--reindex`, with the role index's atomic writer. A floor citation resolves inside `moves/`. Checked at zero cost: `kernel_run_index.py`, `run_index.read_files` and `results.read_directory` all glob non-recursively, and the run-identity tree digest already leaves the whole results directory out, a subdirectory included.

**Activation:** no -- the option set was fixed at the delta-check checkpoint.

## Considered Options

### (a) One directory and one index, schema 3 with a subject kind

Pros: one listing of every subject. Cons: widens the flip gate's stdlib reader and its tests for subjects the adoption ledger never cites; regenerates the committed role index.

### (b) A subdirectory of its own with its own index (chosen)

Pros: the gate, its tests and the role index byte-identical; a move run in progress cannot stale a gated commit. Cons: a reader of all subjects reads two directories; Phase 3's rule-move gate must read `moves/index.json` explicitly.

### (c) Move standings under `roles`

Rejected: labels a move as a role and gives a floor run a flip label it cannot have.

## Consequences

- Positive: REQ-01's gate and index clauses hold without touching the gate.
- Negative: two indexes to keep current; `--reindex` rebuilds both.
