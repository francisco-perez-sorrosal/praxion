## Context

At `SubagentStart`, every inheriting spawn in a managed project receives the three managed core units whole: the coordination protocol, the intermediate-documents rule and the ADR resident. The audience manifest `rules/_audience.yaml` already classifies parts of the first two as `orchestrator-only`, meaning text addressed to the main session, which keeps both rules resident. Those parts make up about 3,200 tokens per spawn (a spike estimate). Lean kernels already exclude them, and two roles cleared paired runs without them.

The consumer evidence: of 111 inheriting spawns in this project's log since 2026-10-10, 109 were `praxion:` roles (verifier 78, implementation-planner 13, context-engineer 6, skill-genesis 6, doc-engineer 5, sentinel 1), plus 1 `general-purpose` and 1 fork. So the split targets plugin roles only. An agent whose content cannot be audited keeps the whole units, which gives up about 2 percent of the saving. The verifier is the main consumer, and its Calibration Verdict needs the tier signals in Process Calibration, an `orchestrator-only` section.

## Decision

1. **Recipients.** A `praxion:<role>` spawn whose definition is read from this plugin and does not set `omitClaudeMd` is a *split recipient*. Every other inheriting spawn is a *whole recipient* and is unchanged. The delivery never depends on which role is spawning.
2. **Channel.** `scripts/generate_kernels.py`, the one regeneration step, writes `claude/kernels/spawn_split.json` (schema 1). For each unit that has dropped spans, the file holds the split text and the sha256 of the hook-read body it was cut from, the sha256 of the audience manifest's bytes, and the sha256 of the split text. The cutter is the new `scripts/kernel_spawn_split.py`, over `kernel_sources` and `kernel_model`. It keeps a section's heading while any of its parts stays.
3. **Currency at spawn.** `hooks/inject_rules.py` reads the JSON and the manifest's bytes at the edge. The pure `hooks/_rule_delivery.py` picks each unit's stored split only when all three digests match the current tree, and the whole body otherwise. Each unit is judged alone. The choice is framed by the unchanged `split_unit`, and the same rule applies on the impaired floor.
4. **Gate.** `check_kernel_manifest.py` adds `I11-spawn-split-drift`, which names the unit when a split recipient's delivery differs from the kernel model's split, a fallback included, and `I11-spawn-split-unreadable` when the artifact does not parse. The `kernel-manifest` hook's read set grows to cover the hook modules the check imports.
5. **Verifier.** The `Calibration Verdict` item points at `rules/swe/swe-agent-coordination-protocol.md` § Process Calibration, read by path. That is one source of truth, with no copy.

## Considered Options

### Build-time split text checked by digest (chosen)

- **Pros:** the hook stays stdlib, pure and small. The manifest keeps its single reader (`kernel_model`) and sections their single cutter (`kernel_sources`). The split survives a missing PyYAML. Regeneration stays one command.
- **Cons:** a generated artifact that can go stale. That is mitigated by the spawn-time digests (stale means whole) and refused at commit (I8, I11).

### Filtering at hook time from the manifest

- **Pros:** nothing generated, nothing to go stale.
- **Cons:** a second YAML reader and a second section cutter inside a hook. A missing PyYAML would cost the split, and the hook already refuses a partial stdlib YAML parser as worse than not running. It also adds latency to every spawn.

### Role-filtered delivery (rejected in round 0)

Delivering by role would add a dimension that every later trial would have to measure. The verifier's need is met by its own definition instead.

## Consequences

- **Positive:**
  - Each of 109 of 111 inheriting spawns sheds the orchestrator-only text, counted at no cost by `scripts/count_spawn_shed.py`.
  - The split protocol unit fits in one part instead of two.
  - Deleting the artifact restores today's delivery exactly.
- **Negative:**
  - Any manifest edit sends both units whole until regeneration. That is allowed, and uncommittable through the gate.
  - The generator and the hook must share one body definition (`_rule_delivery.rule_body`).
  - A plugin role added later is split with no audit row. That is a follow-up: an audited-role set where an unlisted role gets whole delivery, plus audit freshness when a recipient's definition changes.
  - The hook trusts a stored split by its digests alone. A hand edit to `spawn_split.json` that also recomputes the digests is consistent at spawn time; only the commit gate's I11, which re-derives the split from the sources, refuses it. The plugin's own files are trusted at spawn, so this is a declared limit, not a guard to add.
  - The verifier now reaches the tier signals through a pointer it has to follow. If it skips the read, its Calibration Verdict is judged without them, and no mechanical check catches that. Name this in the next verifier trial's notes.
- **Activation:** no. A single load-bearing channel choice with an explicit runner-up was compared against the committed Boundary Assumptions. No lens sweep was needed beyond the Tier 1 self-review.

Near miss, recorded by the verifier's independent re-read: the implementation planner's `Spawn estimate: <n> of <budget>` line is the one place its work touches Process Calibration's envelope bullet. Its own definition names the figures' single source (`coordination-details.md` § Spawn Budget) and states the line it writes, so it acts on its own text, not the dropped bullet, and the bullet's figures reach it by that path.

No entry is reclassified. Whole recipients (`general-purpose`, forks, project, user and other plugins' agents, and an unreadable `praxion:` definition) are outside the split and need no audit.

## Disconfirmation

- **Falsifier:** if I11 cannot be kept green without regenerating on every unrelated edit (the manifest digest churns), or if the runtime digest check falls back on committed trees in managed projects (shown by a split recipient receiving whole while the gate is green), then the whole-file digest is the wrong grain and the channel needs per-unit manifest digests.
- **Steelmanned runner-up:** hook-time filtering has no artifact, no staleness and no regeneration coupling. If PyYAML were guaranteed in every hook interpreter, its single-step freshness would beat a generated file. It loses because PyYAML is not guaranteed and the manifest's single reader is a standing contract.
- **Reversal trigger:** PyYAML becomes a guaranteed hook dependency and `kernel_model` gains a stdlib-only reader, or the artifact's staleness causes a measured loss of saving in managed projects.
