### SIA-Fit Agentic/Eval Archetype (2026-06-05)

Source: research + design run over the external **SIA (Self-Improving AI)** project (`github.com/francisco-perez-sorrosal/sia`). Full artifacts in `.ai-work/sia-praxion-fit/` (`SIA_PRAXION_ENHANCEMENTS.md`, `PLACEMENT_MAP.md`, `CONTEXT_REVIEW.md`, `SYSTEMS_PLAN.md`, three `RESEARCH_FINDINGS_*.md`). **Thesis:** generalize Praxion's self-applied management patterns into a reusable **agentic/eval-driven archetype** — the missing sibling to the mature `ml-training` family — reusing shared machinery (verifier tolerance bands, the `<thing>_reports/+<THING>_LOG.md` pattern, ADRs, fitness functions, the doc-manifest). Six accepted/proposed ADRs ground it (`.ai-state/decisions/drafts/`):

- **SIA-1 — Unified out-of-tree run-storage model** (`dec-draft-9c30645e`) — operational artifacts default out of the repo tree at `$HOME/.<project-name>/` (client-configurable); commit only the curated summary + config. Improves on the current in-tree ML convention. **Spine of the program.**
- **SIA-2 — Pluggable run-store backend abstraction** (`dec-draft-52949236`) — `{local-home / local-custom / s3 / tracker}`, `store_uri` the only varying field; the storage analog of `neo-cloud-abstraction`'s dispatch abstraction. `local-home` is the zero-config reference impl.
- **SIA-3 — `EVAL_RESULTS.md` schema + verifier tolerance-band reuse** (`dec-draft-ccb70b10`) — committed curated summary (root, sibling to `TRAINING_RESULTS.md`) + `.ai-state/eval_ledger/EVAL_LOG.md` aggregate; schema home `skills/agent-evals/references/run-ledger-schema.md`; reuses `rules/ml/eval-driven-verification.md` (feed task accuracy / held-out delta instead of `val_bpb`). Maps to proposals **P2** (run/eval ledger + leaderboard) and **P4** (prompt versioning — `prompt_hash` field).
- **SIA-4 — ML-branch storage reconciliation** (`dec-draft-11bc9d23`, **accepted 2026-06-05**) — migrate the existing in-tree ML conventions onto the unified out-of-tree model (one storage model for all experiment/eval projects). Runs as its own **pre-refactor sub-pipeline** (characterization tests + back-compat); `PRE_REFACTOR_PLAN.md` flagged.
- **SIA-5 — `.ai-state/project_profile.yaml` schema** (`dec-draft-7df1a638`) — machine-consumable archetype/paradigm + `run_store_root` + `eval_framework`, produced as a Phase 8f output. Enables **P1** (onboarding archetype detection + scaffold).
- **SIA-6 — Agentic/eval archetype detection** (`dec-draft-7aac9824`, **provisional**) — broaden `skills/roadmap-synthesis/references/paradigm-detection.md` to fire on LLM-SDK deps + custom `evaluate.py` harnesses (closing the named-framework blind spot); cite-as-canonical from onboarding. **Gated on validation against 2–3 more agentic/eval repos before locking** (anti-SIA-overfit).

Additional proposals from the same run, placement-locked but lighter (no dedicated ADR; see `PLACEMENT_MAP.md`):
- **P3 — Eval hygiene & data-governance** — new path-scoped `rules/eval/eval-data-governance.md` + `agent-evals` reference + `context-security-review` benchmark-leakage detection + sentinel check. Catches answer-key-in-package (SIA ships private ground truth in its wheel) and missing dataset provenance.
- **P5 — Extension-contract conformance + scaffolder** — `skills/architectural-fitness-functions/references/extension-contract-conformance.md` + `claude/aac-templates/fitness-extension-contract.py.tmpl`.
- **P6 — Generated-reference doc-drift check** — `skills/doc-management/references/generated-reference-drift.md` + `doc_manifest.yaml` hook + `doc-engineer` checkpoint.

Sequencing (from `SYSTEMS_PLAN.md`): spine `S0.1 schema → S0.2 backend → S0.3 rules/eval+inventory` → `(P2 ∥ P3)` → `P4` → `P1`; P5/P6 independent; ML migration (SIA-4) as a separate pre-refactor sub-pipeline.
