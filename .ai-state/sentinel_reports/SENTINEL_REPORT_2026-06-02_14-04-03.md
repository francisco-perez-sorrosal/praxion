### Glitches requiring correction

**I1 (Important) — verb name `approve(` at robinhood.md:198**

The word `approve(mode == "human_gate")` at line 198 is a factual error. The contract verb is `authorize()`. This is a one-word fix but matters because an implementer looking for the "human gate interceptor" might search for `authorize` and not find it, or write `approve()` in code.

**I2 (Important) — `hybrid` approval_mode contradiction**

`CapabilityDescriptor.approval_mode` (line 131 of provider-contract.md) declares `"autonomous" | "human_gate" | "hybrid"` as legal values. But `Approval` (the return type of `authorize()`) at line 46 only declares `mode : "autonomous" | "human_gate"`, and the Python class at line 254 uses `Literal["autonomous", "human_gate"]`. These are inconsistent. The likely intended semantics: `hybrid` is a *provider capability* (this provider supports both autonomous and human_gate per-operation), not a value that appears on a specific `Approval` instance. If so, `hybrid` belongs only in `CapabilityDescriptor` and the `Approval.mode` type is correct — but this needs a clarifying comment. If `hybrid` can appear as an `Approval.mode` value (a blended approval state), then both `Approval.mode` definitions need updating.

**I3 (Important) — `alwaysLoad` `.mcp.json` scope tension**

The `alwaysLoad` subsection (lines 146–162) shows a `.mcp.json` config block that contains only `url` (no credentials). This is technically safe to commit. But the two earlier warnings on the same page say "never `project` scope for Robinhood — it commits your OAuth tokens to `.mcp.json`." A reader who (correctly) wires `alwaysLoad` via `.mcp.json` and also (incorrectly) uses `claude mcp add --scope project` will end up with tokens in `.mcp.json`. The `alwaysLoad` block needs an inline note: "This URL-only block is safe to commit; it does not contain OAuth tokens. Keep the MCP token in local scope (keychain) by using `claude mcp add --scope local`."
