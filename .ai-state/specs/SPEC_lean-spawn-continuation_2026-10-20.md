# Spec: lean-spawn-continuation (fix the adherence instrument and close the flip gate's holes before any new trial)

**Task slug**: `lean-spawn-continuation`
**Feature**: The process-adherence instrument and the kernel flip gate made trustworthy before the next paid trial. The instrument stops on repeated identical infrastructure failures, keeps each errored session's evidence, continues or closes a stopped run, binds C5 to roles that ran out of turns, sizes allowances by each run's own discordance and states coverage, seeds launch order, lists earlier runs by measured identity and names transcript directories as the harness does. The gate resolves cited runs through a digest-checked run index, refuses an unreadable parent ledger, reports liveness unknown over a lost segment, accepts `omitClaudeMd` only as a literal true, and owns the eligible roles in a pin moved only in a commit of its own (the implementer now eligible). The startup probe can bill a subscription token file.

## Feature Summary

The lean-spawn pilot closed with an instrument that could not stop on a dead credential, could not resume a stopped run without repaying finished pairs, scored C5 on sessions that never ran out of turns, needed calibration runs it did not have, and a flip gate that trusted record fields it never resolved. This pipeline fixed both before any new trial. Every requirement below was built step by step under the step-loop driver (35 driven steps verified), with seven light reviews (one revise, accepted in round 2), a pre-merge cleanup that split oversized test files and grounded refusal oracles, and a final full-suite run that surfaced six older tests contradicted by the new rules and an eval-suite slowdown (217 to 845 seconds), both fixed test-side.

### REQ-01: An errored session keeps a bounded tail of its evidence

**When** a session of an adherence run ends in an error of any kind
**the system** records with that session the last characters of the session's error output and of its result text, each at most a bound the run declares before its first launch (a stream that is empty is recorded as empty, never omitted), never records the session credential or the API key in either tail (a credential that appears in the output is recorded only in redacted form), and shows each errored session's tails in the report
**so that** the cause of an errored session is read from the results file instead of reproduced by hand, and a committed results file never carries a secret.

### REQ-02: A run stops itself on a repeated identical infrastructure failure

**When** an adherence run is launched
**and** N sessions launched in a row in one arm of one role (a retry counting as the next session of its arm) end in the same counting error kind with the same recorded evidence tail
**the system** records among its declared settings, before its first launch and unchangeable afterwards, the stop count N (a whole number of at least 3, default 3, so that a streak always spans at least two tasks and one task's session and its retry can never stop a run), the error kinds that count toward it (the kinds that mean the session could not run as launched: a timeout, a non-zero exit, a missing or unparseable result, an error result, an undelivered kernel; an evaluation exception never counts), and the masking rule that decides when two tails are the same: equal after every volatile token is masked (identifiers such as UUIDs and other hexadecimal ids of eight or more characters, ISO-8601 timestamps, request ids, durations and byte counts), while two errors whose tails differ in anything else never merge; on the Nth such session launches nothing more (no session, no retry, no judge call), keeps every session already recorded, marks the run incomplete with its stop reason (the error kind, the masked tail, the sessions that formed the streak, and whether the role's other arm ended in the same kind and masked tail inside the streak's window, which alone makes the stop continuable under REQ-03) in the results file and the report, and exits with the incomplete status; any session that ran to a gradeable end, whatever its outcome and isolation breaches included, breaks the streak and never counts toward it, and no graded outcome of any check, no arm's standing against the other and no verdict so far enters the decision
**so that** a dead credential or a broken channel stops spending at once and keeps its evidence, while the stop stays independent of every behavioural outcome the run measures.

### REQ-03: A stopped run is continued or closed, never abandoned for a fresh draw

**When** the operator continues a run whose results record a continuable infrastructure stop (REQ-02: the streak holds sessions of both arms) or a launch refused by the spend cap, or starts a fresh run of a role, or closes a stopped run
**the system** refuses the continuation before anything launches, naming every difference, unless it measures the same thing under the same declarations: the same tree in every path outside `.ai-state/eval_ledger/adherence/` (so committing a results file never invalidates a continuation, while any other change, the adoption ledger included, does), the same resolved model, the same seed, the same planned task list and launch order of every role, and every declared setting unchanged (margin, method, confidence, target, slack, retry policy, stop count, counting kinds and masking rule, tail bound, allowance method, golden-case judging); it also refuses to continue a complete run, a run whose results file is missing or unreadable, a run whose stop was confined to one arm (it stopped spending but is not continuable), a run that stopped for any other reason (an operator interrupt or a crash among them), a run recorded before this change, and a run that already has a continuation (only the latest part of a lineage is continued); when it accepts, it carries over every session the stopped run recorded, treats as never launched only the sessions refused by the spend cap and the sessions inside the stopping streak and inside the other arm's same-kind, same-tail run of errors in that window, launches again, whole, in every arm and in the order its seed gave it, only the planned tasks that have no complete pair and no session ending otherwise, keeps every other session's outcome as recorded (a session of the stopping kind and tail recorded before the streak began, and any pair errored on the lean side alone, stay lean failures under the worst-case recount and are not launched again), gives a relaunched task the declared retry policy afresh, launches no task outside the original plan, and records the harness version each part ran under; it refuses, before launch and naming the stopped run, a fresh run of a role while a stopped run of that role exists that was continuable when it stopped and has been neither continued nor closed; and it closes a stopped run only on the operator's explicit request with a recorded reason, after which that run is listed as a not-clear draw carrying its interim per-check result
**so that** a pair already paid for is never paid for twice, an infrastructure stop never becomes a chance to redraw a pair whose outcome was already counted, and the choice between continuing and starting afresh is never made after seeing the interim counts.

### REQ-04: A continued run counts as one declared run

**When** a continued run finishes, or its verdict, report or listing is read, or an adoption record cites it
**the system** computes one verdict over the counted pairs of its whole lineage under the declarations its first part made before its first launch; names every part of the lineage in order with its id, start, harness version, sessions launched, spend and the stop that ended it; states in the report that the run was continued; lists the lineage once in every earlier-runs listing, never its parts as separate draws; and resolves a citation of any part's id to the whole lineage, its complete pairs and its verdict, so that a record citing a later part passes or fails exactly as one citing the first, and citations of two parts of one lineage count as one run
**so that** a continuation is the one run declared before launch under dec-459, never a fresh draw, and a reader sees where it paused and why.

### REQ-05: The forced-stop check binds only on a role that ran out of turns

**When** a session of an adherence run is graded
**the system** records with the session the number of turns the role itself took, as the harness counted them, and, for a forced early-stop task, the turn cap the role ran under and whether the harness stopped the role at that cap; scores the forced-stop check C5 only on a session whose role the harness stopped at its cap; reports C5 not applicable, with that reason, on a session whose role ended before its cap, and scores that session's return on the pointer-return check C2 as on any task where the role wrote its return; withholds C5, with the reason, on a session whose record cannot establish whether the cap was reached, never binding it on a guess; reports, per role and arm, how many forced-stop sessions ran out of turns and how many ended before their cap, and the differential run-out rate between the arms, neither of which ever gates; lists C5 as not covered, with that reason and in the flip claim, when fewer than five pairs ran out of turns on both sides, so it never gates on fewer and never stays silently unable to fire; and renders a results file written before this change with the outcomes it was graded with, re-scoring no recorded session
**so that** C5 measures what a role leaves behind when it runs out of turns, not whether it judged its report finished on its last turn, its coverage is stated wherever it is too thin to decide, and no recorded verdict moves.

### REQ-06: Mechanical allowances come from the trial's own discordance

**When** an adherence run is launched, or its verdict is computed
**the system** declares before its first launch, unchangeable afterwards (a continuation included), the allowance method: each mechanical check's allowance for a role is the exact one-sided quantile, at the declared confidence, of the net discordance an exchangeable pair of arms would show at that check's own discordant count in this run (the exact critical value of the one-sided paired test over the pairs the verdict counts), one allowance per role and check, never another role's and never the widest across roles; takes no allowance from any calibration run, whatever options the run was given; launches the two arms of each task in an order drawn from the run's seed for that task, recorded with the task, the same for the same seed and kept by a continuation, so that neither arm always takes the first launch slot; states in the report, per mechanical check, its discordant count, its allowance in pairs and in percentage points beside the declared margin; and lists as not covered at the margin, named in the flip claim as a withheld check is today, every mechanical check whose allowance exceeds the margin times its usable pairs
**so that** a mechanical allowance holds its nominal false-regression rate at no extra session, a single discordant pair no longer blocks an unchanged role, and the flip claim never states a bound within the margin for a check whose noise is wider than it.

### REQ-07: Earlier runs are listed by what was measured

**When** an adherence run declares its settings, or its report is rendered
**the system** lists, in order, every earlier run of the same role found beside its results file that measured the same role definition and the same kernel identity (or the same absence of a kernel), whatever checkout commit each ran on, each with its flip verdict; names apart every other earlier run of that role with how its identity differs; lists a calibration run apart, never as a draw; lists a continued run's lineage once; lists a closed run (REQ-03) as a not-clear draw carrying its interim per-check result; lists an earlier run whose results record no identity by the identity its recorded checkout commit held, or as identity unknown when that commit cannot be read, and never drops it; and skips any JSON file beside the results file that is not an adherence results file, naming it in the run's output and in the results file, without stopping the run
**so that** a rerun is visible as a repeated draw however far the checkout moved between runs, and one stray file never stops a run before its first launch.

### REQ-09: A switched record's cited runs resolve to their results

**When** the commit gate judges an adoption ledger holding a record at switched, whether the record is new, changed or unchanged
**the system** resolves every run the record cites, `passing_run` included, to a results file in `.ai-state/eval_ledger/adherence/`, and refuses the commit, naming the role and the run, when a cited run has no readable results file, when its results did not measure that role, when its complete pairs for that role differ from the record's count, when the record's pass flag disagrees with the results' flip verdict for that role, or when the passing run's results show fewer than 20 complete pairs or a verdict other than clear; a citation of any part of a continued run resolves to its whole lineage, its complete pairs and its verdict (REQ-04), so the record is judged the same whichever part it cites; a cited closed run counts as a not-clear draw and never by itself refuses the record
**so that** a switched record cannot rest on a missing, foreign or non-passing run.

### REQ-10: An unreadable parent ledger refuses

**When** the commit gate judges the adoption ledger's moves
**and** the parent commit holds an adoption ledger the gate cannot read

## Acceptance Criteria

Standing constraints, cited below as NN-1 to NN-7:

- **NN-1** Nothing is cut to meet a number: a reduction is a move into an artifact, never a deletion; every claim is bounded non-regression within the declared margin, never improvement.

- **NN-6** Gates stay deterministic and offline, and every refusal this change adds is proven to bite on a known-bad input.
- **NN-7** The flip rule of dec-459 changes only through a recorded amendment after the statistician consult; no recorded session is re-scored and no recorded verdict moves.
