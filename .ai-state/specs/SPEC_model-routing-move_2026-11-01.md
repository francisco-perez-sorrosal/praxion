## Feature Summary

The model-routing tier table leaves session start: the rule loads by path scope and a hook-delivered resident stays.

The task brief's intent was to take the tier table out of what every session loads, because every spawn already routes by its definition's `model:` frontmatter and `scripts/check_model_routing_parity.py` (`ebfdd9e0`) holds that frontmatter equal to the table. The orchestrator-only deviations stay resident: researcher modes, the implementer's step hint, test-engineer acceptance design at `opus`, the discipline-consultant's routine downgrade, the verifier's light review at `sonnet`, and the kill switch. The proof is deterministic, not a paired run: no rule-absent floor can fail, so no paid session ran.

The delivery. A hook-delivered rule cannot be path-scoped (`hooks/inject_rules.py` injects whole bodies and never reads `paths:`), so the parent flips to `install: symlink` with `load: path_scoped`, and Claude Code's native loader fires it when an agent definition or the policy reference is read or edited. The resident is a `hook-deliver` `resident_of` projection reusing `dec-480`'s machinery: it is skipped by the Cursor exporter and the Codex bridge through their existing local checks, every resident line is a line of the parent (kernel check I1), and no role kernel changes. The parent body changes in exactly one place, the `Orchestrator directive` paragraph.

The directive is restated, not carried. The old text told the orchestrator to pass the row's alias as `model` on every spawn and said a skipped alias falls through to the session model. Both are false today: all 17 definitions carry a floor, and the Agent tool's `model` parameter takes only the aliases `sonnet`, `opus`, `haiku` and `fable` (Claude Code subagent docs, read 2026-11-01), so it refuses the `claude-haiku-4-5` pin and invites the `haiku` alias. The new text says a spawn passing no `model` runs at its definition's floor, held equal to the table by the parity gate, and passes a per-spawn `model` only for a listed deviation.

The blacklist keeps its reach. The first non-core resident raised a question `dec-480` never met: the blacklist matches ids by `fnmatch`, so `swe/agent-model-routing` would no longer match the resident and every project disabling it would silently regain the session-start text. `hooks/inject_rules.py` now adds a resident to the disable set when its parent is disabled, through a local check held equal to `scripts/_resident_of.py` by a parity test.

The check. With the table off session start, the claim "spawns route by their definitions" needs a deterministic, $0 reading. `scripts/check_spawn_models.py` and its parser `scripts/spawn_transcripts.py` read each spawn's requested role, any per-spawn model and its prompt markers from the parent transcript, and the model it ran on from the spawn's own transcript, then classify each as `floor`, `override`, `unexplained` or `unknown`. It exits 1 only on an unexplained spawn and starts no model session. It is advisory, not a commit gate (transcripts are local and unversioned).

The measured result. FC-01 reads 19,724 tokens against the 20,273 baseline (a saving of 549, within the 19,773 bound); the spike had estimated 900 to 1,100, but the resident is 753 tokens, about 58% the size of the rule it replaces. FC-02 reads 14,268 (unchanged) and FC-03 reads 0 files over the fail ceiling.

Shape of the delivery: 17 plan steps (10 implementer, 2 test-engineer driver bindings, 5 orchestrator measurement and integration steps); steps 4 to 11, 16 and 17 ran through the step loop; Step 7 carried a forced light review (accepted in round one); Steps 6, 7 and 8 carried `mutation: on`. Steps 16 and 17 are the in-place rework after the first verification.

The verifier's most consequential finding. The new spawn check was green on the driver's synthetic fixtures and wrong on the harness's real transcripts: Claude Code writes each Agent call into an `api-request-blob` record as well (67 of 654 spawn rows were duplicates), and step-loop spawns carry a pointer prompt ("Spawn request: ... Read PROMPT_....md") with no marker, so this pipeline's own sanctioned light-review spawn read `unexplained` and the check exited 1 on its own pipeline. The rework fixed both, and the delta then found that the marker rule the rework set (line start or parenthesised) is narrower than what the orchestrator really writes; that residue is `td-552`.

## Deferred at Close

- **Not measured, with reasons.** Spawn-startup tokens (its only instrument starts a paid session; the routing rule is classified orchestrator-only and no role kernel changes, so a spawn's startup payload has no path to move) and hook latency (no instrument exists; the injector gains at most a frontmatter read of files it already reads). Mid-session reach is not covered by the startup reason (the verifier's W7, now stated in the reader texts).
- **Harness facts carried unchanged, contradicted by current docs (`td-547`, on main).** The rule lists `CLAUDE_CODE_SUBAGENT_MODEL` first as the kill switch (since Claude Code v2.1.251 the order is per-invocation `model`, then frontmatter, then the env var, then the session model, and the env var overrides the others only with `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`), and says the bare `haiku` alias lands on Haiku 3.5 (it resolves to Haiku 5.5 on the Anthropic API and 4.5 on other providers). The same text is always loaded on main today, so this is no regression; the acceptance scenarios pin those tokens, so a Spec Question is the way to change them. The one false sentence the move itself authored ("the kill switch ... overrides every spawn") was corrected in Step 17 and then removed with its clause in `b278d8ef`. The row's fix scope now also names `scripts/check_spawn_models.py` (`_ALIAS_FAMILIES`), which hard-codes `haiku` as the 3.5 family.
- **Declared limits of the move.** A managed project gets the path-scoped table only after `install.sh` reruns (the resident arrives on the plugin update itself; the parent needs a link, and an already-complete marketplace install keeps none until then; low impact, since managed projects do not author Praxion agents and the parity gate holds frontmatter regardless). `agents/**` also fires in a managed project's own `agents/` tree (about 1.3k tokens of table, no wrong guidance; `agents/*.md` would narrow it). Windows ignores user-scope `paths:` (`dec-480`'s declared limit), so the table never path-loads there. Any subagent that reads or edits `agents/**` (the sentinel reads every definition, implementers edit them) now receives the full rule; before this move hook delivery never reached a subagent.
- **The spawn check is advisory, with known precision gaps (`td-552`).** Up to nine historical spawns read `unexplained` because acceptance-design prompts write their marker mid-line and implementer hints arrive in backticks; a step-loop-issued spawn off its floor reads `override` without its model being checked against the routing its request implies; and with the omit-by-default directive a session whose spawns all ran on one family still reads as the kill switch. On the full local corpus the check exits 1, correctly, for 15 historical `doc-engineer` spawns routed up to `sonnet`. It also has no invoker the gate-liveness check counts: see the unledgered GL04 finding under Open Findings.
- **Mutation coverage (`td-549`).** Survivors sit in world-read functions: `hooks/inject_rules.py` 540 of 619 (its tests drive the hook through `subprocess`, so in-process mutants go unobserved), `scripts/regenerate_rules_manifest.py` 111 of 304, `scripts/spawn_transcripts.py` 21 of 179. Deferred by the orchestrator's decision.

### REQ-01: The tier table leaves session start

**When** a session starts in Praxion's checkout or in a managed project, **the system** delivers no tier-table row at session start, and the always-loaded reading lists the session-start routing text in place of the routing rule, **so that** every session saves the table's tokens while staying under the 25,000-token budget.

### REQ-02: The session-start routing text carries the orchestrator's pre-spawn guidance

**When** a session starts, **and** the project has not blacklisted the routing rule, **the system** delivers a routing text that states the resolution order with the kill switch first, the per-spawn lever, the frontmatter floor and the session fallback; the alias note with the Haiku 3.5 trap; and the restated spawn directive with its closed list of sanctioned per-spawn deviations (S-13 to S-16 and S-20), each naming its role, its marker and its model, plus the pointer to the policy reference, **so that** the main session can route every spawn correctly without the table.

### REQ-03: The spawn directive is restated to the contract that holds

**When** the main session reads the routing text, **the system** tells it that a spawn passing no model runs at its definition's floor, which the parity gate holds equal to the tier table, and that a model is passed per spawn only for a listed deviation or under the kill switch, **so that** no text tells the orchestrator to pass an id the Agent tool cannot take, and no text claims a spawn falls through to the session model when its definition carries a floor.

### REQ-04: No statement vanishes

**When** today's rule is compared with the session-start routing text, the path-loaded rule and the policy reference, **the system** shows every statement of the placement table on each surface the table marks, with its evidence tokens, the policy reference gaining the statements marked new there (the aliases' newest-generation tracking and the Haiku 3.5 trap, which it does not carry today), **so that** semantics move between surfaces and none is lost.

### REQ-05: Authors still get the full table by path

**When** a file under `agents/**` or the routing policy reference is read or edited, **the system** loads the full routing rule with its unchanged tier table, **and** it does not load the full rule at session start, **so that** an author changing a definition's model sees the table the parity gate holds it to.

### REQ-06: The blacklist keeps its reach

**When** a project's blacklist file lists `swe/agent-model-routing`, or `swe/*`, **the system** delivers neither the session-start routing text nor the path-loaded rule to that project's sessions, and the injection's summary names what it suppressed, **so that** existing blacklists, the hackathon preset among them, keep removing all routing text as they do today.

### REQ-07: The Codex pipeline adapter is unchanged

**When** the Codex pipeline adapter runs over the shipped tree, **the system** writes model-routing and pipeline-semantics exports equal to the base's after root normalisation, **so that** Codex keeps its tier routes keyed on the same Tier column.

### REQ-08: The Codex rules bridge skips the session-start text

**When** the Codex rules bridge exports the shipped tree, **the system** lists no rule for the session-start routing text, keeps the routing rule excluded from Codex as today, keeps the base's always-on rule ids and session-start pointer text, and differs from the base in the routing rule's entry only by its path scope, **so that** Codex reach is unchanged.

### REQ-09: The Cursor export skips the session-start text

### REQ-10: Gates stay green and still bite

**When** a reader opens the project instructions, the rules catalog, the rules taxonomy doc, the blacklist template, Praxion's own blacklist file, the hackathon preset, the developer readme, the agent-crafting skill or the routing policy reference, **the system** shows no sentence saying the routing rule loads in full at session start or is hook-delivered whole, and each text that described its delivery names its path scope and its session-start text, **so that** no reader acts on a stale delivery claim.

### REQ-12: A spawn-model check stays re-runnable at no cost

**When** the check runs over a directory of recorded session transcripts, **the system** reads each spawn's requested role, any per-spawn model and its prompt markers from the parent transcript and the model it ran on from the spawn's own transcript, and classifies each spawn as matching its definition's floor, a sanctioned override, unexplained, or unknown, exiting non-zero only when some spawn is unexplained (a run whose only findings are unknown spawns exits zero and reports them) and starting no model session. Sanctioned overrides are: any per-spawn model on a researcher, since its modes route up or down; a consultant on `opus` whose prompt does not mark it `routine`, and a consultant on its `sonnet` floor, whether a routine consult or a fall-through to the floor; and the S-14, S-16 and S-20 cases on their markers. A session reads as under the kill switch only when it holds at least two spawns whose floors differ and all of them ran on one model; its spawns are then sanctioned. A spawn reads as unknown when its model is missing, or when it is the only spawn of its session and ran off its floor with no sanctioning marker, since the kill switch cannot be told apart there; such a spawn is never unexplained, **so that** the claim that spawns route by their definitions stays checkable after the table leaves session start.

### REQ-13: Installs link the full rule and not the session-start text

**When** the installer or the marketplace first-session completion links rules, **the system** links the full routing rule into the user rules directory and does not link the session-start routing text, **and** a reinstall over the link set an install made before the move leaves behind yields no dangling link and the same link set a fresh install makes, **so that** the path scope can fire and the session-start text arrives once.

### REQ-14: Eval probes keep probing a hook-delivered rule

**When** the eval suite's probes look for a rule delivered by the session-start injection, **the system** points them at a rule that is still delivered that way, and the eval suite and Praxion's suite pass, **so that** the live sandbox's hook-delivery probe does not silently probe a rule that no longer arrives at session start.

### REQ-15: Earlier frozen observations hold except for declared changes

**When** the outer-loop observations frozen by the ADR-rule move and the kernel pilot are taken over the shipped tree, **the system** matches them for every file this move does not change, and differs only by the declared changes listed under the observable surface, **so that** earlier moves' guarantees survive this one.

## Key Decisions

Four ADR drafts carry the architectural and behavioral decisions; the entries below are from `LEARNINGS.md § Decisions Made`, the plan, the pre-verification digest and the verifier's rulings.

**[systems-architect] The routing rule is path-scoped with a hook-delivered resident (architectural; `dec-483`)**: flip the parent to `install: symlink` with `load: path_scoped` and a path scope; add a `hook-deliver` resident that declares `resident_of`, reusing `dec-480`'s machinery (the draft re-affirms `dec-480`). **Why**: a hook-delivered rule can never be path-scoped (the injector reads no `paths:`), and the resident keeps the session-start text blacklistable and arriving from the plugin root on the plugin update itself; the table stays byte-identical, so the Codex adapter, the parity gate and the pre-commit pattern read what they read today. **Alternatives**: rename, so the resident takes the old path and the table moves to a new file (keeps blacklist ids and eval probes, but breaks the adapter, the parity gate, the pre-commit pattern and every "table lives in" text); keep the parent body byte-identical with a resident of old lines including the stale directive and four table rows (zero test churn, but keeps a false claim resident).

**[systems-architect] Disabling a rule suppresses its resident (behavioral; `dec-482`)**: `hooks/inject_rules.py` adds a hook-deliver rule to the disable set when its frontmatter names a disabled parent in `resident_of`, through a local check held equal to the shared reader by a parity test. **Why**: the blacklist resolves `disable:` globs by `fnmatch` over ids, so without this every project disabling `swe/agent-model-routing`, the hackathon preset among them, would silently regain the session-start text; `swe/*` already matched both. **Alternatives**: carry `resident_of` in the manifest (one generator line, but it changes `dec-480`'s manifest contract and every manifest row reader); a `-resident` name convention (rejected by `dec-480`).

**[systems-architect] The spawn directive is restated to the floor contract (behavioral; `dec-484`)**: omit `model` by default; pass one only for a listed deviation (consultant `opus` unless routine, test-engineer acceptance design `opus`, verifier light review `sonnet`, researcher modes, implementer step hint). **Why**: `dec-078`'s pass-on-every-spawn guarded roles with no floor; today all 17 definitions carry one, the parity gate blocks drift at commit, the old fall-through claim is false, and the always-pass form asks for an id the Agent tool refuses. The always-pass redundancy as a guard against frontmatter drift is replaced by the parity gate and the spawn check. **Alternatives**: keep the always-pass form (it keeps a false fall-through claim resident and asks for an id the tool may refuse, inviting the `haiku` alias, which does not land on the pin).

**[systems-architect] A re-runnable spawn-model check over recorded transcripts (architectural; `dec-485`)**: a new stdlib checker, advisory, exits 1 only on an unexplained spawn, starts no model session. **Why**: no deterministic, $0 reading existed (`check_agent_routing.py` measures delegation with paid sessions; `capture_session.py` records models but judges nothing); its consumers are the verifier of any routing change and the sentinel's routing audit. **Alternatives**: a commit gate (transcripts are local and unversioned); a paid paired run (the brief judged it unneeded, since no rule-absent floor can fail). Its data structures: `Verdict` is a closed `Literal` matched exhaustively; `Spawn` and `Deviation` are frozen values parsed once at the boundary; classification is a pure function of the spawn, its session's spawns and the floors; the sanctioned set is a module constant keyed by role with additive-only evolution and a cross-file checklist comment at both sites (the directive list and the constant move together).

**[systems-architect] Assumptions taken (surfaced, ratified at the phase checkpoint)**: A1 the directive is restated, not kept (its outcome is preserved by frontmatter plus the parity gate; the Agent-tool enum fact started as a memory and Step 5 verified it against current docs); A2 "the routing references" in the path scope means the policy reference only, with `agents/**` as stated; A3 the verifier's light review at `sonnet` joins the closed deviation list; A4 the blacklist's reach is preserved; A5 the kill-switch case is inferred as two or more spawns with differing floors all on one model, since transcripts do not record the environment.

**[implementation-planner] Ordering and tagging (implementation)**: the injector change precedes the delivery flip, so no intermediate commit regains the session-start text for a project that blacklists the rule; the two parametrized reader-text functions were split by parameter so each step owns its nodes exactly once; steps are sequential with no doc-engineer step because the reader texts are production work held by outer-loop nodes; `review: force` on Step 7 and `mutation: on` on Steps 6, 7 and 8. **Why**: one writer at a time keeps the pathspec commits simple, and the flip is the worst case for a stale link. **Alternatives**: flip first, then the injector (a regression window); a doc step per group. ## Gotchas Worth Keeping

- **A reader of a harness-written artifact needs one real recorded example.** The spawn check was green on the driver's synthetic transcripts and wrong on the harness's real layout (`api-request-blob` duplicates, step-loop pointer prompts). The same gap recurred in the rework: the marker rule matched the shapes the outer loop pins, which are narrower than what the orchestrator writes. Put production-shaped transcripts in the fixture set, and run the check over the real corpus before closing.
- **A spec that observes a harness artifact states where each value really lives.** The spec put prompt markers in the parent transcript, but step-loop spawns carry a pointer prompt, so the premise itself was wrong and the fix needed the architect, not the implementer.
- **Footprint rows go stale on any later commit that touches their paths.** The rework changed the resident and the policy reference after the final rows were taken (FP03). Re-take the final rows after every rework commit; the checker reads the latest row and does not judge the limit.
- **Distinguish a sentence the move authored from a fact it carried.** The carried harness facts were not a regression (the same text is always loaded on main); the sentence "the kill switch ... overrides every spawn" was new, written under a requirement that promises "the contract that holds", and false without the force flag. Verify new text against current docs before it ships.
- **A resident is not free.** The saving was 549 tokens against a spike estimate of 900 to 1,100 because the resident (753 tokens) is about 58% the size of the rule it replaces. Size the resident before estimating the saving.
- **A change of reach is a surfaced assumption.** Path scope on `agents/**` delivers the full rule to every subagent that reads or edits a definition, and fires in a managed project's own `agents/` tree; neither was stated until the verifier asked. State a new reach in the reader texts.
- **A delivery sweep greps the whole repository, not only the listed texts.** `rules/CLAUDE.md` and `eval/scripts/inheritance_probe.py` still described the old delivery and were in no step's `Files`; "one-line resident" went stale because this resident is 14 lines.
- **Mutation sensors cannot see subprocess-driven tests.** `hooks/inject_rules.py` scored 540 of 619 survivors because its tests run the hook through `subprocess`; a test that reads the checkout's `agents/` also makes the sensor `run-failed` because it runs from a copied directory. Three harness faults in `hooks/test_inject_rules.py` (a leaked `MUTANT_UNDER_TEST` in the child's environment, a `scripts` import off the path, a by-path module load mutmut counts as no call) made the sensor read `run-failed` on a clean base.
- **A stray `sed -i` backup breaks the fitness gate.** On macOS a BSD `sed -i` backup file (`eval/tests/test_live_materialize.py-e`) failed four `fitness/tests` gates; use the Edit tool, not `sed -i`.
- **A hook-deliver resident of a non-core parent is suppressed with it; a core resident is not.** Marking the routing resident `core: true` would have put it out of the blacklist's reach; the unit test pins the non-core behavior.
- **A pre-commit reciprocity gate scans untracked drafts** (`td-548`): a draft that re-affirms an accepted ADR blocks the commit until the back-link exists; add the `re_affirmed_by` by hand and finalize's rewrite maps it.
- **A shared `.venv` symlinked into scratch copies is rewritten by the liveness run** (`td-546`): use `uv run python -m pytest` when `.venv/bin/pytest` shows a dangling shebang.
