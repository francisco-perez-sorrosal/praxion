# Spec: wal-modes-core (observation log: one owner package + recording modes)

**Task slug**: `wal-modes-core`
**Feature**: The observation log (`.ai-state/observations.jsonl`) gets one owner component -- `hooks/_observation_log/`, holding the mode resolver, an event registry, the writer and the reader -- and three recording modes (`full` = today's behaviour, `standard` = the new default, `off`). Every row says under which mode it was recorded, harness helper stops become a slim `helper_stop` event, every code reader of the log reads through the owner package, and three tests (consumer contract, writer truth, private reader) fail the moment a mode stops recording something a consumer declared it needs. This is the **first half of the `wal-modes` effort** (brief of 2026-09-26); the second half, `wal-retention`, is a separate pipeline with its own archived spec.

## Feature Summary

The observation log had become a load-bearing input to Praxion's process (spawn budget, completion handshake, sentinel P03/P04, the cost collector, the handoff readiness gate) yet had no owner: four writers each applied their own on/off check -- one of them, `record_gate_fire`, ignored the kill switch entirely and leaked rows with observability disabled -- and ten code readers each re-implemented parsing and rotation (td-261). It recorded everything, so `tool_use` was 73% of rows and 77.6% of bytes, and harness-internal helper calls were written as `agent_stop` rows indistinguishable by shape from real agents (td-212: 159 of 184 stops since 2026-09-18, which also produced the published "51 of 524" attribution figure where the truth was 23 of 25 real agents).

This pipeline introduces `hooks/_observation_log/` (stdlib-only; `modes`, `registry`, `writer`, `reader`) as the only write and read path. `PRAXION_OBSERVATION_LOG=full|standard|off` selects the mode; the legacy `PRAXION_DISABLE_OBSERVABILITY` truthy value stays the top-precedence `off`, so the sentinel CI `--settings` override and the hackathon template work with zero edits. `standard`, the new default, keeps every lifecycle, gate, skill, compaction and context-measurement row, every file-changing tool call, and each subagent's first tool call (an append-then-mark temp marker), and drops the other ~82% of `tool_use` rows. A SubagentStop with no prior row and no transcript of its own becomes a slim `helper_stop` row with no transcript scan; the reader upcasts legacy helper rows so every consumer sees one representation. The registry declares each event's fields, the modes that record it and the consumers that need it, and three canary-proven tests enforce it: consumer contracts, writer truth (every real writer driven in-process in all three modes) and private-reader (no module outside the package references the log's filename).

The default change reaches the managed-project fleet at the next plugin release with no file edit (user decision Q3 = A: an explicit `PRAXION_DISABLE_OBSERVABILITY="0"` is neutral and resolves to `standard`); `PRAXION_OBSERVATION_LOG=full` is the documented per-project escape hatch. Retention (N archives behind the single reader), worktree-log merge-in and a log-health sentinel check were deliberately left to `wal-retention` -- the "Not in this decision" clause of `dec-401`.

## Requirements

Verbatim from `SYSTEMS_PLAN.md § Behavioral Specification` (Standard-depth SDD; REQ ids are pipeline-local and appear nowhere in code, tests or docstrings). REQ-04 was marked *pending the user decision* in the plan; the bracketed resolution note is the only edit. REQ-21 was optional and not built.

### Mode resolution

- **REQ-01** When a writer runs and `PRAXION_DISABLE_OBSERVABILITY` is truthy (`1`/`true`/`yes`, case-insensitive), the system resolves the mode to `off` regardless of `PRAXION_OBSERVATION_LOG`. This keeps every existing kill-switch site (CI `--settings`, hackathon template, opted-out projects) producing no log without an edit.
- **REQ-02** When the legacy switch is not truthy and `PRAXION_OBSERVATION_LOG` holds `full`, `standard` or `off` (trimmed, case-insensitive), the system uses that mode. With neither set, it uses `standard`.
- **REQ-03** When `PRAXION_OBSERVATION_LOG` holds any other non-empty value, the system records in `full` with `log_mode_source: invalid-setting` on the `session_start` row. A typo therefore never silently loses evidence.
- **REQ-04** *(resolved 2026-09-26, user decision Q3 = A: an explicit falsy legacy value resolves to `standard`; see Key Decisions)* When `PRAXION_DISABLE_OBSERVABILITY` is explicitly falsy (`0`/`false`/`no`) and `PRAXION_OBSERVATION_LOG` is unset, the system resolves to the user's chosen mode (`standard` per the recommendation below; `full` under option B).

### Recording

- **REQ-05** When the mode is `off`, no writer appends any row: `capture_observations`, `capture_session`, `measure_context_surface`, and `record_gate_fire` at all six gate call sites. `capture_session` also does not upsert the committed summary.
- **REQ-06** When the mode is `standard` and a tool call completes, a `tool_use` row is written if and only if the tool is file-changing, or the call is the first recorded tool call of that subagent in this log. A `Skill` call is still written as `skill_activation`.
- **REQ-07** When two first tool calls of one subagent race, or the first-call marker cannot be read or created, at least one `tool_use` row still exists for that subagent (duplicates acceptable, absence not). A working agent is therefore never read as one that did nothing, whether by P03's WARN/`no_tool_use` split or by the stop-time `unobserved-start`/`unobserved-agent` verdict.
- **REQ-08** When the mode is `full`, every non-blocklisted tool call is written exactly as today.
- **REQ-09** In `full` and `standard`, `session_start`, `session_stop`, `agent_start`, `agent_stop`, `helper_stop`, `compaction`, `context_surface_measurement`, `skill_activation` and `gate_fire` rows are written exactly as today, apart from the added `log_mode` and the `helper_stop` reshaping.
- **REQ-10** Every row a writer appends carries `log_mode` naming the mode it was recorded under. A reader treats a row lacking the key as recorded under `full`, the only policy that existed before modes.

### Helper stops

- **REQ-11** When a SubagentStop arrives whose agent has no prior row in the log tail, and the payload carries the `transcript_path` and `session_id` needed to locate the agent's own transcript, and no such transcript exists (neither the sibling `agent-<id>.jsonl` nor a Workflow-run copy), the system writes a `helper_stop` row with exactly `timestamp`, `session_id`, `agent_id`, `project`, `event_type` and `log_mode`, and scans no transcript.
- **REQ-12** When that check cannot run, or the agent's own transcript exists, the system writes the `agent_stop` row exactly as today, including its `start_correlation` verdict and transcript usage.
- **REQ-13** When the reader returns a legacy `agent_stop` row self-reporting `start_correlation: unobserved-agent` whose `usage_source` is neither `subagent-transcript` nor `parent-transcript`, it presents the row as `helper_stop`. Every consumer then sees one helper representation across old and new rows.
- **REQ-14** When P03 runs over a log containing `helper_stop` rows, it pairs on them and reports them under `unmatched_stops.unobserved-agent` (or `producer_log_disagreement`) exactly as it treated the equivalent legacy rows. `workflow_run_cost.py` lists them in its `unobserved` section as before.

### Reader

- **REQ-15** When any code consumer reads the log, it reads through the owner package's reader. Each consumer's segment coverage is unchanged: active only, active + `.1`, tail-bounded, or active + windowed `.1`.
- **REQ-16** When a segment is missing or unreadable, the reader returns a named reason and no rows. It skips malformed lines, reporting their line numbers and count, and it never raises.

### Contracts and gates

- **REQ-17** When the registry stops `standard` from recording an event class or field a consumer declared at `min_mode: standard`, the consumer-contract test fails.
- **REQ-18** When a writer's output in some mode disagrees with the registry's recording table or declared fields, the writer-truth test fails.
- **REQ-19** When a Python module outside the owner package and its named allowlist references the log's filename, the private-reader test fails.
- **REQ-20** When sentinel P04 judges tool rows carrying `log_mode: standard`, it judges only the write-surface half and states that the grant half requires `full`.
- **REQ-21** *(optional)* When `PRAXION_DISABLE_EVENT_POSTING` or the legacy switch is set, `send_event.py` exits before importing `urllib.request` and `subprocess`.

## Key Decisions

Two ADRs landed (`dec-401` architectural, `dec-400` behavioral) plus one user decision at planning; the eight architect decisions are D1-D8 of `SYSTEMS_PLAN.md § Decisions` (context copied from there and from `LEARNINGS.md § Decisions Made`).

**[systems-architect] D1 -- One owner package `hooks/_observation_log/` with registry, modes, writer and reader (`dec-401`)**: all writers and readers go through it. **Why**: the mode decision needs one table, and the table is trustworthy only if the code that consults it on write is the code tested against it; scattered per-writer checks recreate the exact defect where `record_gate_fire` ignored the switch. A package rather than a file because the registry changes when consumers change, the reader when retention changes (the next pipeline), the writer when recording policy changes; it also keeps `fcntl` out of readers and the reader off the per-tool-call path. **Alternatives**: a shared reader only with per-writer mode checks (fewest files, but repeats the check in four writers); a single ~550-line file with four reasons to change. **Accepted cost**: a ~15-file migration in one pipeline, mitigated by behaviour-identical characterization tests sequenced first.

**[systems-architect] D2 (Q1) -- `standard` keeps a first-tool-call-per-subagent row (`dec-401`)**: file-changing tools from any agent plus each subagent's first tool call of any kind, "first" decided by an append-then-mark temp marker keyed by (log directory identity, `agent_id`). **Why**: P03's WARN vs `no_tool_use` split and the writer's own stop-time `unobserved-start` vs `unobserved-agent` verdict both need "this agent did anything" in the log at write time. **Alternatives**: transcript existence (off-log, ~30-day expiry, fragile cwd mapping, cannot serve the writer's verdict); all subagent tool calls (keeps 77% of tool rows, too little saving to justify a mode). Keeps 18% of `tool_use` rows. **Accepted cost**: one empty temp file per subagent per log and a `stat`/`open` per subagent tool call; a purged marker yields a harmless duplicate row (at-least-once invariant). The P04 grant half goes `full`-only because plugin `tools:` grants are harness-enforced.

**[systems-architect] D3 (td-212) -- helper stops become a slim `helper_stop` event type in every mode (`dec-400`, partially supersedes `dec-370` clause 2's representation)**: argued against the brief's proposal to collapse helpers into a per-session count. **Why**: a count still costs one filesystem write per helper, adds cross-invocation mutable state to async, concurrent, fail-open hooks, and has a structural race (59 of 159 recent helpers arrive right after `session_stop`); it would also change P03's substrate and blind `workflow_run_cost`'s helper section. The split fixes td-212's actual harms -- consumers counting helpers as agents, the `unknown` agent-type bucket, a ~53 ms parent-transcript stream per helper -- with no new state and exact counts. **Alternatives**: collapse to a count; keep as `agent_stop` + `unobserved-agent`. **Accepted cost**: helper rows stay in the log (slim); the cost collector's census stops counting helpers, old and new alike, via the upcast -- a deliberate correction named in the ADR.

**[systems-architect] D4 (Q4) -- a new setting key with the legacy switch as an overriding umbrella (`dec-401`)**: `PRAXION_OBSERVATION_LOG=full|standard|off`; a truthy `PRAXION_DISABLE_OBSERVABILITY` overrides to `off`. **Why**: uses the transport every surface already carries (onboarding's settings block, the hackathon template, the sentinel CI `--settings` that outranks project settings per `dec-399`), so no file edit is needed anywhere. **Alternatives**: repurpose the legacy key's values (overloads a boolean-named key); a Praxion config file (a reader in every hook for no transport the settings block lacks). **Accepted cost**: two keys to document; a user setting the new key to `off` must be told it does not stop chronograph posting.

**[systems-architect] D5-D8 (`dec-401`)**: every row declares `log_mode` (and `session_start` also the source), so "absent" vs "not recorded" is decidable from any row without a join -- about 21 bytes per row, and a legacy row without the key reads as `full`; session-grain series (`skill_activation`, `compaction`, `context_surface_measurement`) stay in `standard` because they are under 1% of bytes and dropping `skill_activation` would silently reverse `dec-269`'s purpose; the reader returns dict rows plus one upcaster rather than typed row classes, turning ten migrations into ten small diffs (typed rows are the next increment); no intermediate mode, because no named consumer sits between `full` and `standard`.

**[main-agent] User decision Q3 = A, 2026-09-26**: an explicit `PRAXION_DISABLE_OBSERVABILITY="0"` with no `PRAXION_OBSERVATION_LOG` resolves to `standard`. **Why**: the literal meaning of `"0"` is "not disabled"; onboarding writes the key in every mode, so option B (`"0"` means `full`) would make the new default practically inert for managed projects. **Alternatives**: B (needs a `LEGACY_ENABLE` source and one precedence rule); C (`full` now, migrate later via a second fleet change). No code was needed -- REQ-02's existing precedence already yields `standard`. **Accepted cost**: a fleet behaviour change at the next release, disclosed in a release-note line naming the `full` escape hatch.

**[implementation-planner] Plan-shape decisions (no ADR; they fail the `architectural` test)**: docs folded into the implementer's final step rather than a parallel doc-engineer group, and the optional `send_event.py` lazy imports folded into that step, both to fit the stated spawn envelope; sequential-only plan.

**Verification stage (orchestrator and verifier)**: the forced light review of Step 6 returned FAIL with three real defects fixed before verification -- a `Skill` first call consumed the first-call marker, `off` still wrote the committed summary, and the mode setting was case-sensitive. Round 1 then failed on proof, not behaviour: the writer-truth gate covered one writer of five (FAIL-1) and `traceability.yml` had not been maintained after Step 2 (FAIL-2). The seven-row rework loop closed both, plus the upcast relabelling new rows (WARN-1), P03 reading an unreadable log as clean (WARN-2), `off` still doing expensive work in two hooks (WARN-8) and the ADR/DESIGN wording (WARN-4/7). Round 2 deferred td-208, td-271, td-272, td-273, td-274, td-275, td-276, td-280 and td-281.

**First half of `wal-modes`.** The remaining half of the effort -- N archives behind the single reader, worktree-log merge-in at merge/teardown, and a log-health sentinel check -- is the `wal-retention` pipeline, built on the single reader this feature delivered; it archives its own spec, which points back here.
