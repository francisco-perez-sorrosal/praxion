# Research Findings: Practitioner patterns for lean resident context (lens: practitioner-patterns)

**Completed phases**: all (scoping, harness facts, Q1-Q5, catalogue, divergence pass, synthesis)

## Research Goal
Identify how reputable practitioners and other agent harnesses keep coding agents' resident (startup) context small while preserving guidance quality, and which of those patterns a Claude Code *plugin* like Praxion can actually implement.

## Research Questions
1. What do reputable practitioners advise about lean startup context and large instruction corpora?
2. How do other harnesses scope resident instructions (activation modes, budgets, lazy triggers)?
3. Which concrete patterns fit a large first-party corpus (router/index, skills-as-filesystem, keyword/classifier injection, JIT rules, profiles, subagent isolation, kernel+on-demand, cache-friendly ordering)?
4. What before/after measurements exist (tokens, cost, task success), with setup?
5. What anti-patterns and failure stories are documented?

Tag legend: **VERIFIED** = primary source fetched 2026-10-11; **SINGLE-SOURCE** = one source / one vendor's own numbers; **ASSUMPTION** = inference, falsifier named where possible. Source tier: T1 official docs / peer-reviewed, T2 preprint / OSS repo, T3 practitioner or vendor post, T4 forum / secondary summary.

### Claude Code harness facts relevant to every pattern below (all VERIFIED, code.claude.com fetched 2026-10-11)
- **Plugins cannot ship always-on instructions.** "A `CLAUDE.md` at the plugin root isn't loaded as context ... To include instructions that load into Claude's context, put them in a skill." Plugin `settings.json` honours only `agent` and `subagentStatusLine`. Rules load only from `~/.claude/rules/`, `.claude/rules/` (project) and nested dirs. => Praxion's always-on rules reach sessions only through `install.sh` symlinks into `~/.claude/rules/` (user scope) or through hook injection. [plugins-reference]
- **Path-scoped rules are lazy**: a rule with `paths:` loads when Read/Write/Edit (or a single-file `cat`/`head`) touches a matching file; rules without `paths:` load at launch. `paths` is the only frontmatter field read. [memory]
- **Imports don't save context**: "`@path` imports ... help organization but don't reduce context, since imported files load at launch." [memory]
- **Size guidance**: "target under 200 lines per CLAUDE.md file"; startup warning when files exceed the length or "add up past a combined limit". Block HTML comments are stripped before injection (free maintainer notes). [memory]
- **Auto memory**: first 200 lines or 25KB of `MEMORY.md` load every session; topic files are on demand. [memory]
- **`claudeMdExcludes`** (any settings layer, arrays merge) can exclude CLAUDE.md and rules files by glob, including symlinked rules (both link path and target match since v2.1.239). [memory]
- **Subagents** load the full CLAUDE.md hierarchy "including `~/.claude/CLAUDE.md`, project rules ..." unless the agent sets **`omitClaudeMd: true`** (v2.1.271+; skips user/project/local CLAUDE.md files; managed policy still loads). Built-in Explore/Plan skip CLAUDE.md. `skills:` preload injects full bodies (first 32 names). Subagents get no skill listing at startup but can call `Skill`. Agent `memory:` adds 200 lines/25KB of that agent's MEMORY.md. Whether `omitClaudeMd` also drops `~/.claude/rules/*.md` is not stated explicitly — ASSUMPTION to test (the doc lists "project rules" in the inherited set and names only CLAUDE.md files in the opt-out). [sub-agents]
- **Skill listing**: budget "scales at 1% of the model's context window"; overflow drops descriptions starting with the least-invoked skills (names always kept); per-entry cap 1,536 chars (`skillListingMaxDescChars`); raise via `skillListingBudgetFraction` or `SLASH_COMMAND_TOOL_CHAR_BUDGET`. Skill `paths:` frontmatter limits auto-activation to matching files. **"Plugin skills are not affected by `skillOverrides`"** — this explains Praxion's td-197 null result. `disable-model-invocation: true` removes the description from context but also blocks preload and model invocation. [skills]
- **Skill lifecycle**: an invoked SKILL.md stays in the conversation; after compaction the most recent invocation of each skill is re-attached, first 5,000 tokens each, 25,000 tokens combined. [skills]
- **Hooks**: `SessionStart`, `SubagentStart`, `UserPromptSubmit`, `PreToolUse`/`PostToolUse` etc. can add `additionalContext`; each string capped at **10,000 characters** (overflow is saved to a file with a 2,000-char preview, and "Claude Code doesn't ask Claude to read the file"). Plugin hooks support the same events and also run inside subagents. `SubagentStart` additionalContext lands at the start of the subagent's conversation. `InstructionsLoaded` observes (load reasons `session_start`, `nested_traversal`, `path_glob_match`, `include`, `compact`) but cannot block or modify. No hook can remove resident content. [hooks]
- **Plugin enablement**: `defaultEnabled`, `dependencies`, and `enabledPlugins` (settings) make it possible to split a plugin into several and enable them per project — a harness-supported profile mechanism. [plugins-reference]
- **Official guidance**: "Bloated CLAUDE.md files cause Claude to ignore your actual instructions!"; "If Claude already does something correctly without the instruction, delete it or convert it to a hook"; "If you emphasize many lines, none of them stands out"; `/doctor` proposes cuts. [best-practices]

## External Findings
### Q1 Practitioner guidance

**Strong convergence (≥2 independent traditions): resident content must be minimal, non-discoverable, and pruned against observed failures.**
- **Anthropic (T1, VERIFIED)** — "the smallest set of high-signal tokens that maximize the likelihood of your desired outcome"; context rot as a finite "attention budget"; start minimal on the best model and add instructions only for observed failures; Claude Code is itself a *hybrid*: "CLAUDE.md files are loaded up front, while glob and grep retrieve files as needed" ([Effective context engineering, 2025-09-29](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). Best practices: "For each line, ask: *Would removing this cause Claude to make mistakes?* If not, cut it. Bloated CLAUDE.md files cause Claude to ignore your actual instructions!"; knowledge "only relevant sometimes" belongs in skills ([best-practices](https://code.claude.com/docs/en/best-practices)).
- **ETH Zurich / LogicStar (T2 preprint, ICLR 2026 submission, VERIFIED)** — context files *reduce* success on average while raising cost >20%: LLM-generated files −0.5% (SWE-bench Lite) / −2% (AGENTbench), cost +20% / +23%, +2.45 / +3.92 steps; developer-written files ≈ +4% success but up to +19% cost, helping every agent *except Claude Code (Sonnet 4.5)*. Agents *did* follow the files; the harm comes from "unnecessary requirements" that drive broader exploration. Recommendation: "describe only minimal requirements" ([arXiv 2602.11988](https://arxiv.org/html/2602.11988v1); setup: Claude Code/Sonnet-4.5, Codex/GPT-5.2 and GPT-5.1-mini, Qwen Code/Qwen3-30b-coder; 300 SWE-bench Lite + 138 AGENTbench tasks; Python only; files are repo-overview style, not a Praxion-style process corpus).
- **HumanLayer (T3, VERIFIED)** — "Frontier thinking LLMs can follow ~150-200 instructions with reasonable consistency"; Claude Code's system prompt already holds "~50"; degradation is *uniform* ("ignore all of them uniformly"); root CLAUDE.md "less than sixty lines"; "Prefer pointers to copies" ([Writing a good CLAUDE.md, 2025-11-25](https://www.humanlayer.dev/blog/writing-a-good-claude-md)). The 150-200 figure cites IFScale (arXiv 2507.11538) — SINGLE-SOURCE via the post; "~50 instructions" is the author's own harness analysis (SINGLE-SOURCE).
- **Addy Osmani (T3, VERIFIED)** — treat AGENTS.md as "a living list of codebase smells you haven't fixed yet"; delete what is discoverable from code; fix the codebase (linter, tests) before adding context; a minimal protocol file that *routes* to task-type files; a maintenance subagent to keep it current ([Stop Using /init, 2026-02-23](https://addyosmani.com/blog/agents-md/)). Cites Lulla et al. (ICSE JAWs 2026): human AGENTS.md on 124 PRs → median runtime −28.64%, output tokens −16.58%, *correctness not measured* (SINGLE-SOURCE via Osmani; paper not fetched).
- **Shrivu Shankar (T3, VERIFIED)** — monorepo CLAUDE.md "strictly maintained" at 13KB, with "effectively a max token count for each internal tool's documentation"; "start small, documenting based on what Claude is getting wrong"; a bare path mention is often ignored — "You have to *pitch* the agent on *why* and *when* to read the file"; fresh-session baseline "~20k tokens (10%)" ([How I use every Claude Code feature, 2025-11-02](https://blog.sshh.io/p/how-i-use-every-claude-code-feature)).
- **Mario Zechner (T3, VERIFIED)** — pi's system prompt + tools "below 1000 tokens", only AGENTS.md appended; Playwright MCP (21 tools, 13.7k tokens) and Chrome DevTools MCP (26 tools, 18k) eat "7–9% of the context window before work begins"; CLIs with READMEs read on demand; Terminal-Bench 2.0 results exist only as images (minimal Terminus 2 "is holding its own") ([pi, 2025-11-30](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)). "Minimal harness ≈ parity" is SINGLE-SOURCE and not quantified in text.
- **Birgitta Böckeler / Thoughtworks (T3, VERIFIED)** — classifies context by *who decides to load it*: the LLM (skills, MCP — never certain), the human (slash commands), the agent software (hooks — deterministic); "build context like rules files up gradually"; warns of an "illusion of control" ([Context Engineering for Coding Agents, 2026-02-05](https://martinfowler.com/articles/exploring-gen-ai/context-engineering-coding-agents.html)).

**Progressive disclosure / skills (convergent: Anthropic, Willison, OpenAI Codex, Amp, plus the "description" modes in Cursor/Windsurf/Kiro).**
- Anthropic: three levels — metadata pre-loaded, SKILL.md on relevance, linked files "only as needed"; bundled context "effectively unbounded" ([Agent Skills, 2025-10-16](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills), VERIFIED).
- Simon Willison: "each skill only takes up a few dozen extra tokens" vs GitHub MCP "tens of thousands"; caveat: needs a filesystem ([2025-10-16](https://simonwillison.net/2025/Oct/16/claude-skills/), VERIFIED).

**Counter-evidence: passive context beats LLM-decided loading for knowledge the agent must always apply.**
- **Vercel (T3 vendor eval, SINGLE-SOURCE; fetched)** — Next.js 16 APIs absent from training data: baseline 53%; skill default 53% ("never invoked in 56% of eval cases"); skill + explicit instructions 79%; **8KB compressed docs index in AGENTS.md 100%** (compressed from ~40KB, no loss). Explanation: "No decision point", "Consistent availability", "No ordering issues". Wording sensitivity: "invoke first" vs "explore first" changed outcomes. Model, agent and eval count not stated ([Jude Gao, 2026-01-27](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals)). The winner is an **index of pointers** to doc files, not the docs — which matches the prior spike's "context carries an index, not the library".
- **Jesse Vincent / superpowers (T3, VERIFIED)** — skills did not reliably self-trigger; the fix was a `SessionStart` hook injecting a short bootstrap ("If you have a skill to do something, you must use it"), strengthened after each failed pressure test; skills tested on subagents under realistic pressure scenarios ("TDD for skills") ([Superpowers, 2025-10-09](https://blog.fsck.com/2025/10/09/superpowers/)).

**Isolation (convergent, with a named dissent).**
- Anthropic: subagents return "often 1,000-2,000 tokens"; Dex Horthy: "Subagents are about context control", keep utilization "in the 40%-60% range", research → plan → implement with frequent intentional compaction ([ace-fca.md](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/ace-fca.md), VERIFIED, date inferred ~Aug 2025); Lance Martin's *isolate* ([2025-06-23](https://rlancemartin.github.io/2025/06/23/context_engineering/), VERIFIED); Breunig's *context quarantine* ([2025-06-26](https://www.dbreunig.com/2025/06/26/how-to-fix-your-context.html), VERIFIED).
- Dissent: Cognition (Walden Yan) — "Share context, and share full agent traces"; subagents fine for answering questions, fragile for writing code ([Don't Build Multi-Agents, 2025-06-12](https://cognition.com/blog/dont-build-multi-agents), VERIFIED); Shankar calls custom specialist subagents "a brittle solution" (prefers "Master-Clone"); Zechner: "zero visibility". The dissent is about *decision fragmentation*, not context cost.

**KV-cache discipline (convergent: Manus + Claude Code team).**
- Manus (Yichao "Peak" Ji): "the KV-cache hit rate is the single most important metric for a production-stage AI agent"; ~100:1 input:output; cached Sonnet input 0.30 vs 3 USD/MTok; stable prefix, append-only, deterministic serialization; **mask, don't remove** tools; the file system as restorable context; recitation via todo.md ([2025-07-18](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus), VERIFIED).
- Thariq Shihipar (Claude Code team): "we run alerts on our prompt cache hit rate and declare SEVs if they're too low"; "Use messages instead of system prompt changes"; never add or remove tools mid-session — plan mode is a tool, deferred tools are stable stubs ([Prompt caching is everything, 2026-04-30](https://claude.dev/blog/lessons-from-building-claude-code-prompt-caching-is-everything/), VERIFIED).
- Claude Code request layering (T1, VERIFIED): System prompt + tools → Project context (CLAUDE.md, auto memory, unscoped rules; changes only at session start, `/clear`, `/compact`) → Conversation. Skills, plan mode, plugin skills/agents/hooks, path-scoped rules and hook `additionalContext` all **append** to the conversation and keep the cache. The cache is scoped per machine + directory; sequential sessions share the prefix only when the startup git-status snapshot matches; subagents never read the parent's cache (5-minute TTL by default); forks do ([prompt-caching](https://code.claude.com/docs/en/prompt-caching)).

**Taxonomies.** Lance Martin: write / select / compress / isolate. Breunig's failure modes: poisoning; distraction (Gemini agent repeating past actions "significantly beyond 100k"; Databricks: Llama 3.1 405b correctness falls ~32k); confusion (quantized Llama 3.1 8B fails with 46 tools, succeeds with 19; >30 tools descriptions overlap; RAG tool selection "up to 3x"); clash (sharded multi-turn prompts −39% average, o3 98.1→64.1) ([How Long Contexts Fail, 2025-06-22](https://www.dbreunig.com/2025/06/22/how-contexts-fail-and-how-to-fix-them.html), VERIFIED; the numbers belong to the cited papers and are SINGLE-SOURCE here). Factory injects a generated repo overview at session start ("saves thousands of exploratory tokens"; no metrics) plus user/org memory ([2025-08-25](https://factory.com/news/context-window-problem), VERIFIED, qualitative).

**Cross-harness convergence (VERIFIED, ≥5 independent vendors):** the **four activation modes** — *always*, *file-glob*, *model-decided by description*, *manual* — are now common vocabulary (Cursor, Windsurf, Kiro, Claude Code, Cline, Copilot). Only OpenHands adds *keyword triggers*; Gemini CLI, Amp and Claude Code document *directory-touch* JIT loading. Hard **byte budgets** exist only in Codex (32 KiB docs; 2% / 8,000 chars skills), Windsurf (6K / 12K chars) and Claude Code (1% skills; 10K hook strings); everyone else relies on advice. Codex puts the skill's *path* in the listing, so the model can read the file directly — a small design difference worth noting for a router.
### Q3 Patterns for a large first-party corpus

What the 2026 field converged on, organised by the job each pattern does. Plugin fit is analysed in the catalogue below.

1. **Kernel + index resident, bodies on demand.** Anthropic ("Think of this file as giving Claude an overview"; CLAUDE.md as index — [Steering Claude Code, 2026-06-18](https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more)), HumanLayer (`agent_docs/` pointers), Osmani (protocol file routes to persona/skill files), Vercel (8KB compressed docs *index* beat on-demand skills), Hermes (skill index in prompt → `skill_view` → assets), Pi (XML skill index read with the ordinary read tool). The resident part carries *what exists and when to read it*, not the content. Shankar's caveat matters: a bare path is often ignored — the index must say *why and when* to read each target.
2. **Activation-mode tiering (always / glob / description / manual).** Five-plus harnesses (Q2 table). For a corpus, every unit gets an explicit activation mode instead of defaulting to *always*. Claude Code supports *glob* for rules and skills (`paths:`), *description* for skills, *manual* via `disable-model-invocation`; it has **no description-decided mode for rules** (Cursor's "Apply Intelligently", Windsurf `model_decision`, Kiro `auto` have it). A description-decided rule must therefore be expressed as a skill.
3. **Deferred loading as the near-universal skill pattern.** "Eight of nine adopters load only skill metadata up front"; OpenClaw is the lone eager loader ([Harness Engineering, arXiv 2609.00006, 2026-07-15](https://arxiv.org/html/2609.00006), VERIFIED; T2 preprint, 11 harnesses audited from source). Praxion's 240,647 tokens of agent `skills:` preloads is the eager pattern this study finds the field abandoning.
4. **Conditional activation / gating pushes JIT into the extension layer.** Claude Code `paths:` skills, OpenHands PathTrigger rules, OpenClaw eligibility gating (skills whose required binaries/env are absent never reach the prompt), Mistral Vibe JIT nested AGENTS.md, Gemini CLI/Amp directory-touch loading ([arXiv 2609.00006 §12.5, §9](https://arxiv.org/html/2609.00006), VERIFIED).
5. **Keyword / classifier injection via hooks.** OpenHands `triggers:` (harness-native); in Claude Code it is built by users on `UserPromptSubmit`: superpowers bootstrap; diet103-style `skill-rules.json` (keywords, intent patterns, globs, enforcement levels — known only via third-party reproductions, T4); Scott Spence's forced-eval and Haiku llm-eval hooks (measured, Q4); Pilot Shell (word-boundary matching, trigger scoring, cap of three — T4 snippet). Mechanism is cache-safe in Claude Code (hook output appends to the conversation) but every injection stays in history for the rest of the session.
6. **Prose policy → deterministic configuration.** Claude Code docs ("delete it or convert it to a hook"; hooks are "deterministic and guarantee the action happens"), HumanLayer ("CLAUDE.md is not a linter"; Stop hook runs formatters), Osmani ("fix the codebase first ... add a linter rule"), Shankar (block-at-submit commit hook), and the 2026 source study: "behavioral policy migrating from prompt prose to configuration" — Codex dropped no-commit / anti-gold-plating prose for feature flags; Mistral Vibe removed its "Never Commit" rule ([arXiv 2609.00006 §14.5](https://arxiv.org/html/2609.00006)). Four independent traditions.
7. **Subagent isolation for heavy context**, with two sub-patterns: (a) *lean spawn* — subagent receives only what the delegation prompt carries (Claude Code `omitClaudeMd`, built-in Explore/Plan skip CLAUDE.md; Hermes injects a frozen memory snapshot capped at 2,200 chars; Claude Code freezes the parent's rendered prompt at fork so children hit the cache); (b) *summary return* (1-2K tokens). Dissent recorded in Q1.
8. **Per-project profiles / toggles.** Codex `[[skills.config]] enabled=false`; Cursor/Cline per-rule toggles; Windsurf/Cursor enterprise "system"/"team" rules; Claude Code plugin scopes (user / project / local `enabledPlugins`, local overrides project overrides user), `defaultEnabled:false`, `dependencies` ([plugins/install](https://code.claude.com/docs/en/plugins/install), VERIFIED). A corpus can be split into a core plugin plus opt-in domain plugins enabled per project.
9. **Hard byte budgets with CI enforcement.** Codex `project_doc_max_bytes` 32 KiB and skills ≤2%/8,000 chars; Windsurf 6K/12K chars; Claude Code 1% listing, 10K-char hook strings, 200-line CLAUDE.md warning; Shankar's per-tool token allocation; Hermes 2,200/1,375-char memory files. Claude Code now reports per-plugin "Always-on" tokens (`claude plugin details <name>`) and per-plugin "Every turn" / "When invoked" estimates in `/plugin` ([plugins/install](https://code.claude.com/docs/en/plugins/install), VERIFIED) — a native measurement surface.
10. **KV-cache-friendly ordering.** Static first, dynamic last; never mutate the system/tool layer mid-session; inject updates as messages (Manus; Claude Code team; Hermes "bit-perfect normalized" prefix with date-only timestamp; OpenHands static/dynamic two-block system message). Claude Code already enforces this for its own layers; a plugin's remaining responsibility is to keep **per-session-variable data out of always-loaded files** (they sit in the cached project-context layer, and sequential sessions only share it when identical) and to keep subagent prompts byte-stable across spawns so same-type spawns within the 5-minute TTL reuse each other's cache (ASSUMPTION — follows from prefix matching; falsifier: `cache_read_input_tokens` ≈ 0 on a second identical spawn).
11. **Recitation / restorable compression.** Manus todo.md, Horthy's research/plan files, OPENDEV's "event-driven system reminders" against instruction fade-out ([arXiv 2603.05344](https://arxiv.org/abs/2603.05344), abstract only, VERIFIED). Relevant as the *quality* counterweight: a lean kernel can be re-surfaced at the moment it matters (e.g., a PreToolUse reminder before `git commit`) instead of being resident all session.

### Q5 Anti-patterns and failure stories

1. **Kitchen-sink instruction file → uniform ignoring.** Anthropic: "If your CLAUDE.md is too long, Claude ignores half of it"; "If you emphasize many lines, none of them stands out" ([best-practices](https://code.claude.com/docs/en/best-practices)). HumanLayer: degradation is uniform. ETH: unnecessary requirements make tasks harder and costlier. (VERIFIED, 3 traditions)
2. **Auto-generated / discoverable content.** ETH: generated files duplicate docs and hurt (nearly all contained codebase overviews, per Osmani); HumanLayer and Osmani: don't `/init`; Anthropic exclude-list: "Anything Claude can figure out by reading code", "File-by-file descriptions". (VERIFIED)
3. **Historical / legacy patterns anchor the model wrong** (Osmani's tRPC example — hypothetical). Stale content "performs worse" (Osmani). (VERIFIED as claim; hypothetical example)
4. **Moving always-needed conventions into skills → they silently stop applying.** Vercel: skill not invoked in 56% of cases; Spence: no-hook activation ~50-55%; superpowers needed a forcing bootstrap; Praxion's own telemetry (12 `Skill` calls in 18,042 rows). Secondary guide: rules in a skill are missed "on the 80% of tasks where the skill never activates" (T4). (Convergent across 3 independent sources; magnitudes SINGLE-SOURCE)
5. **Path-scoped rules that never match, or vanish after compaction.** Docs: path-scoped rules load into message history on trigger, "compaction summarizes them away"; "If a rule must persist across compaction, drop the `paths:` frontmatter" ([context-window](https://code.claude.com/docs/en/context-window)). Praxion already logs the related limitation that path rules inject on Read, not Write/Edit. The Anthropic *Steering* blog's table contradicts the docs on compaction (Divergence D6). (VERIFIED)
6. **Hooks that inject too much.** anthropics/claude-code#15554 (closed 2025-12-28): SessionStart hooks injecting ~6MB of doc TOCs plus a tree caused "Prompt is too long" before the first prompt; #70460 (closed 2026-06-23): output over ~10,000 chars silently became a file path + 2KB preview — now documented behavior: "Claude Code doesn't ask Claude to read the file, so keep anything Claude must always see within the cap" ([hooks](https://code.claude.com/docs/en/hooks)). (VERIFIED via `gh issue view`)
7. **Over-eager classifier injection.** Spence's llm-eval hook hallucinated skill recommendations on unrelated prompts (4 false positives / 5 true-negative cases). Each `UserPromptSubmit` injection persists in history, so a chatty hook compounds per turn. (SINGLE-SOURCE + mechanism VERIFIED)
8. **Cache-busting mutations.** Manus: a per-second timestamp at the prompt head invalidates the cache; non-deterministic JSON key order; removing tools mid-task. Claude Code team: never change tools or models mid-session; skills whose frontmatter names another `model` cause a full uncached turn ([prompt-caching](https://code.claude.com/docs/en/prompt-caching)). Claude Code design neutralises most plugin-side risks (hooks/skills append), but **enabling/disabling an MCP-bearing plugin, or toggling tools without tool search, invalidates the cache**. (VERIFIED)
9. **Injected text that reads like a command** "can trigger Claude's prompt-injection defenses"; `<system-reminder>` tags are escaped ([hooks](https://code.claude.com/docs/en/hooks)). Relevant to Praxion's injected rule/ADR blocks: write them as factual statements. (VERIFIED)
10. **Specialist subagents with partial context** make conflicting implicit decisions (Cognition's Flappy Bird example); hidden context "a brittle solution" (Shankar); "zero visibility" (Zechner). Applies when a lean-spawn diet strips context a writer subagent needed. (VERIFIED, 3 practitioners)
11. **Bare path mentions are ignored** — "if you just *mention* the path, Claude will often ignore it" (Shankar); Claude Code memory docs: a CLAUDE.md "that tells Claude in words to read AGENTS.md" is read "only if it decides to open the file". An index that lists pointers without a trigger condition degrades to nothing. (VERIFIED, 2 sources)
12. **Imports as fake savings.** `@path` imports "don't reduce context, since imported files load at launch" ([memory](https://code.claude.com/docs/en/memory)). (VERIFIED)
13. **Skill descriptions silently dropped.** Overflow drops descriptions of the least-invoked skills first — a self-reinforcing loop where rarely used skills become harder to trigger ([skills](https://code.claude.com/docs/en/skills)). (VERIFIED; the loop is ASSUMPTION)

## Strongest patterns for Praxion

The researcher's read of the evidence, not a design decision; the architect decides. Each one has ≥2 independent traditions behind it and a plugin- or installer-implementable path.

1. **Kernel + routed index, replacing most always-on rule prose (patterns 1, 2, 12).** Evidence: Anthropic docs and *Steering* post, ETH ("minimal requirements"), HumanLayer, Osmani, Vercel (index > on-demand skills), Hermes/Pi index designs. Why it fits: Praxion's ~13.4K always-on rules plus ~8K MEMORY.md are exactly the "large resident manual" every source warns against, and Praxion already distributes rules through its installer, so it can ship a small kernel + generated index without harness changes. Guard against the two documented failures: every index row needs a *trigger condition* (Shankar; anti-pattern 11), and conventions needed on most turns stay in the kernel (anti-pattern 4; Vercel).
2. **Convert enforceable prose into hooks/scripts (pattern 6).** Four traditions plus the 2026 source study showing harness vendors themselves moving policy from prose to configuration. Praxion already has commit gates, worktree guards and a hook stack, so many always-on "MUST/never" lines (git conventions, ADR id rules, token-budget rules) may be enforced rather than recited. This is the only pattern that *raises* guidance reliability while removing tokens.
3. **Stop eager preloading in subagents; make spawns lean (patterns 3, 7a, 11).** The field abandoned eager skill loading (8/9 harnesses); Praxion preloads 240,647 tokens across 17 agents while measuring 12 on-demand `Skill` calls. Candidate levers: `omitClaudeMd: true` on agents whose delegation prompt carries their context (needs a probe — see Open Questions), a role kernel via `SubagentStart` additionalContext (≤10,000 chars, plugin-native, runs in subagents), and pointer lists instead of full preloads. Counter-evidence to respect: Cognition's partial-context failures apply to *writer* agents more than to readers/reviewers.
4. **Deterministic activation for the long tail (patterns 4, 5).** Self-triggering is weak (Vercel 56% never invoked; Spence ~50% baseline; superpowers needed a forcing bootstrap; Praxion's telemetry), so a leaner resident set needs a reliable way to surface what was moved out: skill `paths:` globs where a file type predicts need, and a short `UserPromptSubmit` matcher that injects *pointers* (not bodies) on keyword/intent match, capped (Pilot Shell's cap-of-three idea). Measured gains are single-source; must be validated on Praxion's own prompts.
5. **Budget each surface and measure with native tools (pattern 9).** Codex/Windsurf/Hermes show hard caps work as an engineering constraint; Claude Code now exposes per-plugin Always-on tokens (`claude plugin details`), `/doctor` listing cost, `/skill-doctor`, `InstructionsLoaded` logging, and `claude plugin eval` with a `tool_used: Skill` grader. These make a before/after on Praxion's own corpus possible — which matters because **no external study measured a process corpus like Praxion's**.

Weaker for Praxion right now: per-project plugin profiles (pattern 8 — real harness support, but packaging churn and onboarding contract changes; best as a second step after 1-3), and cache-ordering work (pattern 10 — Claude Code already layers requests; only hygiene remains).
