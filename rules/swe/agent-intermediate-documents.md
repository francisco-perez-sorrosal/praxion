## Agent Intermediate Documents

Agent documents live in two locations by lifecycle: **`.ai-work/<task-slug>/`** — ephemeral pipeline intermediates, gitignored, deleted after use — and **`.ai-state/`** — persistent project intelligence, committed to git. The canonical file trees for both, with each artifact's writers, readers, shape and lifetime, live in [`artifact-inventory.md`](../../skills/software-planning/references/artifact-inventory.md#directory-trees) — read it on demand before writing or consuming a specific artifact.

### `.ai-work/` — Ephemeral Pipeline Documents

- **Exclusively for pipeline documents** — the outputs defined in the [SWE agent coordination protocol](swe-agent-coordination-protocol.md); never command scratch files, project docs, ADRs, build artifacts or tool caches.

#### Task Slug Convention

Every run uses its own `<task-slug>/` subdirectory. The slug is **kebab-case** (2–4 words, e.g. `auth-flow`), generated by the **main agent** at pipeline start, included in every subagent prompt (`Task slug: <slug>`), used for all `.ai-work/` reads/writes, and inherited unchanged downstream — isolating each pipeline's state from concurrent runs. Full propagation contract: [`coordination-details.md` § Task Slug Propagation](../../skills/software-planning/references/coordination-details.md#task-slug-propagation).

### `.ai-state/` — Persistent Project Intelligence

- **Always committed**, except the local raw observations WAL. In a worktree, `.ai-state/` changes land on the pipeline branch and are reconciled at merge ([.ai-state/ reconciliation](../../skills/software-planning/references/agent-pipeline-details.md#ai-state-reconciliation-for-worktree-merges)).
- **Lifecycle states** decide what an *absent* artifact means: `active` — a real gap; `optional-lazy` — the feature was not adopted; `threshold-lazy` — the project is below the growth threshold; `future-designed` — the producer is designed but not wired. Per-artifact assignment: the inventory.

#### `TECH_DEBT_LEDGER.md` + `TECH_DEBT_RESOLVED.md` — living tech-debt ledger pair {#tech_debt_ledger-summary}

`TECH_DEBT_LEDGER.md` (`status ∈ {open, in-flight}`) and `TECH_DEBT_RESOLVED.md` (`status ∈ {resolved, wontfix}`) share one `td-NNN` namespace. **Writers (only four):** verifier, sentinel, orchestrator, architect-validator. **Consumers** update status in place but never add rows. LEDGER is append-only; terminal rows migrate to RESOLVED at post-merge. Schema, owner-role heuristic and worktree concurrency: [`tech-debt-ledger.md`](../../skills/software-planning/references/tech-debt-ledger.md) — the single schema anchor.

### Document Lifecycle

**Ephemeral** (`.ai-work/<task-slug>/`, one run — merge `VERIFICATION_REPORT.md` patterns into `LEARNINGS.md` before deletion) · **Session-persistent** (`IMPLEMENTATION_PLAN.md` / `WIP.md` / `LEARNINGS.md`, deleted at pipeline end) · **Permanent** (`.ai-state/` + `docs/architecture.md`). Full table: [inventory § Document Lifecycle](../../skills/software-planning/references/artifact-inventory.md#document-lifecycle-full-table).

### Version Control and Cleanup

- **Never commit `.ai-work/`** (gitignored). **Always commit `.ai-state/`**, except the local raw WAL.
- Clean up with `rm -rf .ai-work/<task-slug>/` after pipeline completion — `LEARNINGS.md` prose is `/skill-genesis`-harvested-or-lost; remove `.ai-work/` itself only when every task directory has been cleaned.

### Parallel Execution

When agents run concurrently, each writes a scoped fragment file instead of the canonical document; the supervising agent merges fragments once all complete. `CONTEXT_REVIEW.md` is cumulative and single-writer (context-engineer only) — exempt. Fragment naming + reconciliation: [coordination-details.md § Parallel Execution](../../skills/software-planning/references/coordination-details.md#parallel-execution-fragment-files); semantic reconciliation protocols: [agent-pipeline-details.md](../../skills/software-planning/references/agent-pipeline-details.md).
