# Scripts

Utility and operational scripts for the Praxion ecosystem.

## Available Scripts

- `praxion-hackathon` — Launch Claude Code in hackathon mode with launch-time context trimming: passes `--disable-slash-commands` (~5–8K skill tokens trimmed), `--effort low`, `--append-system-prompt` (from `.claude/hackathon-directive.md`), and `--settings` (`.claude/hackathon-settings.json`). Mode activation (env var, CLAUDE.md block, rules preset) is project-scoped and works on any launch; this wrapper adds the skill-surface trim layer that `settings.json` cannot. Use `scripts/praxion-hackathon --resume` to re-attach. Set `PRAXION_HACKATHON_NO_PS1=1` to suppress the `[hackathon]` PS1 prefix. Dogfooding copy — template source at `claude/aac-templates/praxion-hackathon.sh.tmpl`
- `praxion-claude-dev` — Launch Claude Code with the Praxion working tree as the plugin source (wraps `claude --plugin-dir`). Passes `--dangerously-skip-permissions` by default; set `PRAXION_DEV_SAFE=1` to keep prompts. See [Session-scoped local testing](../README_DEV.md#session-scoped-local-testing)
- `praxion-parallel` — Launch N parallel Claude Code sessions in Warp (default) or iTerm2, each visually distinguished by per-tab color and title, each in its own git worktree via `claude --worktree`. Supports `--worktrees new|existing|none`, per-session `--names`, `--tasks`, and `--append-system-prompts` (pipe-separated, for recipe-style role assignment); `-y/--yolo` for `--dangerously-skip-permissions`. Warp backend writes an ephemeral Launch Configuration under `~/.warp/launch_configurations/` and invokes `open warp://launch/<name>`; iTerm2 backend drives `osascript` and sends OSC-6 escape sequences for per-tab color. `--dry-run` prints the spawn plan. `--ui [PROJECT]` hands off to `praxion-parallel-ui` (the ephemeral web launcher). Replaces the legacy tmux-based `ccwt`
- `praxion-parallel-ui` — Ephemeral localhost launcher for `praxion-parallel`. Stdlib-only Python (`http.server`), binds `127.0.0.1` on a kernel-chosen port, prints a single-use 32-byte URL token, opens the user's default browser. The single-page UI composes a multi-session launch — project, terminal, worktree mode, per-session name/task/system-prompt/`/color` — submits to the bash engine via `POST /api/launch`, and the server self-terminates after the first successful launch (or 10 min idle). User recipes persist at `~/.config/praxion-parallel/recipes.json`; project-local recipes at `<project>/.praxion/recipes.json` (precedence `builtin < user < project`); six built-in templates (`solo-work`, `implement-and-test`, `team-lead`, `compare-implementations`, `feature-fan-out`, `overnight-autonomous`) ship under `scripts/praxion_parallel_ui_assets/`. **Praxion-aware mode** activates automatically on projects with `.ai-state/`: the per-session `agent` field replaces explicit `system_prompt` (auto-derives "Operate as the Praxion @<agent>..." at submit time), worktree name auto-fills from the agent, and the agents dropdown is populated from `<project>/agents/`, the marketplace cache, or a hardcoded fallback. Inspired by named-preset patterns in community tools (Codeman, Nimbalyst)
- `chronograph-ctl` — Development helper for the Task Chronograph MCP server (start/stop/restart/status/logs from source)
- `phoenix-ctl` — Manage the Phoenix observability daemon (install/start/stop/restart/status/uninstall via launchd)
- `reconcile_ai_state.py` — Post-merge reconciliation for `.ai-state/` artifacts: observations.jsonl dedup, ADR renumbering, index regeneration. Called by `/merge-worktree`
- `reconcile_pipeline_state.py` — Pipeline step-completion reconciler for truncation recovery. Side-effect-free reader: classifies every `WIP.md` step against ground truth (`git diff` + `TEST_RESULTS.md` is the arbiter; `.ai-state/observations.jsonl` WAL is a localization hint) into per-step verdicts (`verified-complete` / `mismatch` / `partial@<pt>` / `in-flight` / `unknown` / `pending`), emitting JSON on stdout (exit 0 clean / 1 recovery-needed / 2 unknown / 3 error). Ground truth — not the checkbox — drives `verified-complete`, so a step whose files are all changed but still `- [ ]` is caught (the died-before-checkbox case); ambiguous correlation degrades to `unknown`, never a guessed verdict. Resolves repo root from `--repo-root` / `git rev-parse`, never `__file__`; refuses plugin-cache paths. Driven by `/resume-pipeline`. Tests + gate-liveness canary in `scripts/test_reconcile_pipeline_state.py`
- `regenerate_adr_index.py` — Regenerate `.ai-state/decisions/DECISIONS_INDEX.md` from ADR file frontmatter
- `finalize_adrs.py` — Promote fragment ADRs under `.ai-state/decisions/drafts/` to stable `<NNN>-<slug>.md`, rewrite `dec-draft-<hash>` cross-references across a bounded allowlist (sibling ADRs; `.ai-state/DESIGN.md` + tech-debt ledger pair + `.ai-state/CONSULT_LEDGER.md` + `.ai-state/SYSTEM_DEPLOYMENT.md` + project-root `ROADMAP.md`; `docs/**/*.md`; `.ai-work/*/LEARNINGS.md` / `SYSTEMS_PLAN.md` / `IMPLEMENTATION_PLAN.md`; matching `SPEC_*`, separator-insensitively), regenerate the index. Because a bounded allowlist fails silently by construction — a file outside it is indistinguishable from a file with no matches — `detect_unrewritten_ids()` re-scans a wider net (`.ai-state/**/*.md` + `docs/**/*.md`) after every rewrite for the concrete ids just promoted, and logs a WARNING naming any file the scope missed. Non-blocking; matching concrete ids rather than the `dec-draft-<hash>` shape keeps teaching placeholders out of the findings. Resolves the repo root from `--repo-root` (passed by the chain) or `git rev-parse --show-toplevel`, never from `__file__`, and refuses to run against a plugin-cache path. Per-draft skip-with-warning on a malformed id. Idempotent; advisory file lock. Invoked by the finalize hook chain (post-merge / post-commit / post-checkout) and `/merge-worktree`
- `check_adr_frontmatter_promotion.py` — Flags a finalized ADR under `.ai-state/decisions/<NNN>-<slug>.md` whose frontmatter `id` disagrees with its filename `NNN`, or whose `status` is still `proposed` — the exact shape a `finalize_adrs.py` staging defect (td-103) shipped once. STATE gate (current file bytes, not history), so it lives here rather than `fitness/tests/`, reaching CI via `test.yml`'s unfiltered `test-root` job. `--staged` reads git index blobs (`git show :<path>`) instead of the working tree — the mode wired into `.pre-commit-config.yaml`, since the defect ships a correct working tree over a stale staged blob. An unrecognized `.md` file under the directory is reported unclassified rather than silently skipped. `--json` for machine output, `--repo-root` for tests. Resolves the repo root via `_repo_root.resolve_repo_root`, never `__file__`. Stdlib-only. Exit codes: 0 clean, 1 violations, 2 script error. Tests + canaries in `scripts/test_check_adr_frontmatter_promotion.py`
- `finalize_tech_debt_ledger.py` — Collapse duplicate rows in `.ai-state/TECH_DEBT_LEDGER.md` by `dedup_key`. Status precedence on collapse is `resolved > in-flight > open > wontfix`; tie-break by newer `last-seen`; non-conflicting fields merged (earliest `first-seen`; notes concatenated with ` // `; locations union-sorted). Idempotent; advisory file lock; fail-loud on malformed rows (exit 1). Invoked by the finalize hook chain after `finalize_adrs.py`. See `rules/swe/agent-intermediate-documents.md` § `TECH_DEBT_LEDGER.md`
- `adr_health.py` — ADR **reference-decay classifier**. For every `affected_files` entry that no longer resolves, classifies *why* into seven causes — `placeholder-shape`, `out-of-repo`, `lazy-artifact`, `renamed`, `removed-by-self`, `removed-by-later`, `vanished` — because only the last means "retire" and a naive existence check flags every "remove X" decision as stale, inverting the truth on the most load-bearing records. `removed-by-later` is the highest-value output: it reconstructs supersession edges that exist in reality but were never recorded. Reuses `validate_adr_references.parse_affected_files` rather than re-implementing it; builds deletion and rename indexes with **two** git calls total (per-path `git log` would be ~1,400 subprocesses). **Advisory by construction** — emits candidates, never edits an ADR or a `status`, exit 0 always. When git history or the lifecycle table is unavailable, the dependent classes are **withheld with a named reason** rather than defaulted to `vanished` — including `vanished` itself, which is a dependent class (it means every repair class was *tried* and none matched, true only when every oracle answered), so an unavailable oracle yields `unclassified`/no-disposition rather than a retirement candidate. The lifecycle table resolves from the project root **first and the plugin's own tree second**: it is plugin reference data that no onboarding phase writes into a managed project, so a project-root-only lookup left the oracle permanently unavailable everywhere except this repository. Decisions at a terminal `status` are excluded (their references are history, not a live index) and counted in `skipped_terminal`; `retired` ones are probed in the reverse direction, so a retired decision whose paths resolve again surfaces in `reopen_candidates` — retirement stays reversible instead of becoming a one-way delete. Also reports `category_mix` (corpus + recent-window counts and the recent `architectural` share) — a **measurement, not a gate**: whether a decision changed the component inventory is not derivable from frontmatter, so the `architectural` test cannot be checked mechanically, but its effect can be watched against the adoption baseline. Counts terminal decisions too, since categorisation is an authoring question and retiring a record must not flatter the ratio. Consumed by the sentinel's DH dimension (`--json`); also runnable standalone (`--class <name>` filters). **Installed on `PATH` by `install_claude.sh`** so the shipped [`/decisions`](../commands/decisions.md) command can call it in user projects — the executable bit is what the installer filters on, so removing it silently un-ships the command's only data source. Sibling imports resolve through the symlink to the real `scripts/` directory, so `_repo_root.py` and `validate_adr_references.py` need no link of their own. Tests + per-class canaries in `scripts/test_adr_health.py`
- `check_architecture_projection.py` — Reconciles the LikeC4 model against `.ai-state/DESIGN.md` §3a: every structural component must have a row and every row must name an element. The binding is **explicit** — each row carries the element id in an `Element` column — because row and element titles legitimately differ ("Agent runtime / Pipeline" vs "Agent Pipeline"), so title matching would both miss real drift and invent false drift on a rename; carrying the id in the doc also puts the binding in front of a human reader. *Structural* means no child component: the four layer containers get no row, while a component whose only children are agents or documents does. Four finding kinds (`element-without-row`, `row-without-element`, `unknown-element`, `not-structural`); resolving one is a judgment about which side is right, so it never edits either. A **second reconciliation covers the published half**: §4's canonical-block rows against the `BLOCKS` registry in `sync_canonical_blocks.py` (`block-without-row` / `row-without-block`) — those blocks are installed into every managed project's own `CLAUDE.md`, so an undocumented one costs N repositories rather than this one. The registry is **parsed from `repo_root`, not imported from `sys.path`**, so `--repo-root` relocates both authorities instead of reconciling one tree's design doc against another tree's registry, and the checker never executes code from the tree it inspects; a non-literal registry key withholds rather than part-reading. An unreadable registry **withholds** that half rather than reporting that nothing ships. Stdlib-only, `--json`, `--repo-root`; exit 1 on findings, so it doubles as the `architecture-projection` pre-commit gate (which must stay wired to `claude/canonical-blocks/` as well as the model and DESIGN.md, since adding a block touches neither of the latter). Also consumed by sentinel AC13. Tests + canaries for all four kinds in `scripts/test_check_architecture_projection.py`
- `measure_token_budget.py` — The always-loaded token budget, **measured**. Counts real tokens via the Anthropic `count_tokens` endpoint when `ANTHROPIC_API_KEY` is set; without one it falls back to a **labelled** `bytes / 3.6` estimate and says so, because reporting an estimate as a measurement is how a folk divisor became load-bearing in the first place. Both halves of the old problem are fixed here: the **file set is code** (`always_loaded_files()` — `rules/**/*.md` lacking `paths:`, minus catalog `README.md`, plus the project and global `CLAUDE.md`), where it had been a prose sentence three readers applied three ways; and the **size is measured**, where sites variously said `/3.5`, `/3.6` and `~3.6-4.0` — which at the 2026-08-05 corpus straddled the ceiling, one reporting a breach and another headroom over identical bytes. Measured that day: 88,599 bytes → **23,341 tokens**, a true ratio of **3.796 chars/token**, against which `/3.5` errs 8.5% high and `/3.6` 5.4% high. The fallback stays 3.6 *because* it errs high — a guardrail should overestimate. Stdlib-only for a specific reason: the sentinel invokes it through the ambient interpreter, so a third-party import would make it a finding of `check_gate_liveness.py`'s own `ambient-import` check. `--json`, `--repo-root`; exit 1 when over budget, so it doubles as a gate. Consumed by sentinel **T02**, which is forbidden from restating a divisor. Tests + an over-budget canary in `scripts/test_measure_token_budget.py`
- `check_gate_liveness.py` — Mechanically decidable clauses of `rules/swe/gate-liveness.md`. Three checks from one `--json` run: `forbidden-pattern` (**GL02**, a scan for a pattern another rule forbids there, so it can never match), `uninvoked-gate` (**GL04**, a `check_*`/`validate_*` script nothing calls — a gate's own tests are deliberately not invocation sites), and `ambient-import` (**GL05**, a script an agent or command runs with a bare `python3` that needs a package the ambient interpreter may not hold). GL04 and GL05 are the two halves of *existence is not operation*, and passing GL04 while failing GL05 is the more dangerous order — the call site exists, so the wiring looks complete. Three properties of `ambient-import` are load-bearing rather than thorough: it follows sibling imports **transitively** (the instance it was built against imported only stdlib plus one sibling, and the dependency lived in the sibling); it exempts `try`/`except ImportError` guards but never the handler's own fallback import, which fails identically; and its scope is `agents/*.md` + `commands/*.md` only, since hooks, CI and `.pre-commit-config.yaml` each declare their own interpreter. **Stdlib-only for a specific reason** — it is itself ambient-invoked, so a third-party import would make it the first finding of its own check. `--check <name>|all`, `--root`, `--json`; exit 1 on findings, so it doubles as a commit gate; inline `gate-liveness:ignore` escape. Canaries + inverse guards per check in `scripts/test_check_gate_liveness.py`
- `check_metrics_freshness.py` — **TD06**: does the newest `METRICS_REPORT_*.json` still describe current `HEAD`? A metrics report is a photograph of one commit, and the sentinel's TD dimension reads it later to write `td-NNN` rows five agents consume — between shutter and reading, the subject moves. **Days are the wrong unit and that is the whole point.** The prior policy asked whether the report was older than 14 days; the incident it missed was 6 days old (fresh by that rule) sitting behind ~180 commits, one of which had decomposed the very file ranked #1. So this measures commit distance and, more precisely, asks the only question admitting an exact answer: *has this hotspot's file been touched since the report was taken?* — per-path, threshold-free. `commits_since` and `age_days` are reported as **context, never as the gate**; inventing a commit threshold would reproduce the original defect in a new unit. Distance alone is explicitly not staleness (a hundred commits elsewhere leave a ranking valid), which an inverse guard pins. **Withholds rather than guesses**: a report predating `run_metadata.commit` has an *unrecoverable* commit distance — no filename or log records the analysed SHA — so `withheld` is a distinct status with a named reason, never a silent `fresh`, because collapsing "unanswerable" into "clean" is how the original gap stayed invisible. Same for a commit this clone has never seen. Stdlib-only for the usual reason — the sentinel invokes it through the ambient interpreter, so a third-party import would make it a finding of `check_gate_liveness.py`'s `ambient-import` check. `--json`, `--repo-root`, `--reports-dir`; exit 1 on `stale`. Enabled by the `generated_at`/`commit`/`dirty` provenance fields `scripts.project_metrics` writes into `run_metadata` (a deliberate **patch** bump — trends compare major.minor, so a minor bump would sever trend continuity for an additive change). Canaries in `scripts/test_check_metrics_freshness.py`, including a reconstruction of the historical near-miss and a discriminating case that is fresh by age and stale by commit distance
- `check_spec_drift.py` / `spec_drift.py` — SH07 sentinel wrapper over the pure spec↔artifact drift detector. The wrapper emits sentinel rows for archived specs under `.ai-state/specs/`, deferring `orphaned-edge` to SH01/SH04; `detect_drift` dispatches by scope to the in-flight path (reads `.ai-work/<task-slug>/traceability.yml`) or the archived one. **PyYAML is imported on demand, never at module scope**: only the in-flight scope reaches it and the sentinel walks the archived one, so a module-level import made the whole gate unloadable under the bare `python3` its own call site prescribes (found by GL05; pinned by `test_module_imports_without_pyyaml_present`). A missing PyYAML **raises, naming `sys.executable`**, rather than degrading to `{}` — which is indistinguishable from "declares no requirements", so swallowing it would make a drift detector report clean exactly when it could not read its input. Tests in `tests/test_spec_drift.py`, `tests/test_sh07_sentinel.py`, `scripts/test_check_spec_drift.py`

- `finalize_chain.sh` — Sourceable bash library: shared library powering the finalize hook chain. Path resolution that follows symlinks (works for both copy-installed and symlink-installed hooks), state-driven gate predicates (`on_main`, `drafts_present`, `state_was_touched`), and the three public entry points consumed by the dispatcher: `finalize_chain_post_merge`, `finalize_chain_post_commit`, `finalize_chain_post_checkout`. State-triggered semantics ensure draft ADRs landing on main via any path eventually promote. **Interpreter resolution** (`_finalize_chain_python`): `$PRAXION_PYTHON` → `<repo>/.venv/bin/python` → ambient `python3`. A bare `python3` is not necessarily an interpreter holding the project's declared dependencies — under a pyenv shim it can be an unrelated build, which silently stranded `build_doc_manifest.py` (needs PyYAML) and let the committed manifest drift while every commit printed a non-blocking warning. The ambient fallback keeps stdlib-only finalizers working in consumer projects with no venv, so the resolution strictly widens what runs

- `check_state_ledgers.py` — The parser `.ai-state/` never had. Its ledgers are a data format with a written specification and no reader: every writer is an agent following prose, every invariant lives in a sibling markdown file, and the only feedback was whether a downstream consumer happened to notice — which is how 49 rows drifted their `dedup_key` with every commit green. Validates five registered ledgers for field count, row-inside-table, delimiter termination, literal pipes (the table delimiter, which silently splits a row into an extra cell), and tech-debt `dedup_key` format, value and cross-file uniqueness. `unterminated-row` is the shape nobody had named: a line opening with a delimiter and not closing with one is skipped in silence by every grep recipe *and* by `finalize_tech_debt_ledger.py`. Membership is an explicit registry rather than a directory scan — most `.ai-state/*.md` are prose — and the registry's own drift surface is closed by failing when a top-level `.ai-state/*.md` declares a `**Schema**:` line and is not registered. Row identity is a per-ledger first-cell signature, which is what lets one detector serve both structural shapes: the tech-debt tables running to EOF and the CONSULT tables followed by prose sections. Format description (registry, parser, `dedup_key` derivation) lives in the sibling `state_ledger_schema.py`, kept out of this catalog for the same reason the other private siblings are. `--check` / `--repo-root`; exit 1 on blocking violations, advisory findings reported at exit 0. Wired as the `state-ledger-schema` pre-commit hook **and** a blocking CI job — pre-commit alone fires only when a ledger is staged, which is exactly how the drift accumulated. Canary + inverse guard per check in `scripts/test_check_state_ledgers.py`
- `check_frontmatter_parses.py` — Parses the YAML frontmatter of every shipped artifact **with a real parser**. Nothing in the repo did: the sentinel's `C04`/`S01`/`S02` grep for field *presence*, and a grep for `description:` succeeds on a file no loader can read — verbatim the anti-pattern `rules/swe/gate-liveness.md` names. Two commands shipped with unparseable frontmatter (`argument-hint: [<a>] [--b <c>]` is two flow sequences on one line) and every presence-grep stayed green throughout; a command whose frontmatter does not load cannot register its `description`, the sole model-invocation mechanism. Scope is deliberately narrow — *if a file declares frontmatter, it must load and must be a mapping* — with **one named exception**: `argument-hint` must load as `str`. That field alone earns a type assertion because the corpus is read by two parser classes that disagree (the Cursor/Codex exporters parse line-by-line with a regex and coerce to `str`, never erroring; Claude Code and this gate use real YAML and see a `list`), which is how 21 string-valued and 15 list-valued hints coexisted unnoticed. PyYAML is required rather than hand-rolled — a parser free to disagree with the loader it stands in for is not a gate — and deferred behind `_require_yaml` so a bare `python3` *raises naming `sys.executable`* instead of reporting clean (GL05). Wired as pre-commit `artifact-frontmatter-parse` (Block B5) with `additional_dependencies: ['pyyaml']`. Four finding kinds; canary + inverse guard per kind in `scripts/test_check_frontmatter_parses.py`
- `check_agent_shared_blocks.py` — Holds the prose blocks replicated inline across agent definitions byte-identical to a single source of truth. The task-slug scoping paragraph is inlined in 15 agents and **cannot be extracted** (agents inherit no rules/CLAUDE.md content, and plugin-distributed agents cannot read runtime reference files), and it had already forked into four tails. The canonical text is a module constant here rather than a `claude/canonical-blocks/` entry on purpose: every mechanism in that directory keys off the `BLOCKS` registry rather than a directory listing, so an unregistered file there is a stowaway no mechanism can see — and this is a mid-paragraph *sentence* with per-agent lead-ins, not a fenced section. Carriers are **detected, not enumerated** (a hardcoded list is itself a drift vector); the comparison unit is the canonical sentence anchored at ``The **task slug**`` and spanning exactly its own length, so per-agent lead-in clauses (`Determine…`, `Before gathering information…`) and trailing context are not drift, while a tell without the anchor is `anchor-missing`. `--print-canonical` emits the exact bytes so the authority is obtainable rather than merely asserted. Stdlib-only. Wired as pre-commit `agent-shared-blocks` (Block B6), with the script itself in the hook's `files:` pattern so editing the source of truth re-runs the comparison. Canaries for all three historical tails in `scripts/test_check_agent_shared_blocks.py`
- `resolve_test_scope.py` — The change-detection tooling the test-topology trunk schema names but never had. `file_dependencies` was a declared field no consumer read; without a reader it is a dead seam, and the topology it belongs to is a static document rather than a working radius. Maps changed paths to the groups in `.ai-state/TEST_TOPOLOGY.md`, applies the trunk's tier closure (`step` none / `phase` one-hop / `pipeline` all), and emits concrete pytest invocations — keeping `parallel_safe: false` groups in their own sequential call. **Its load-bearing property is that an unmatched path WIDENS the radius**: a changed file matching no group escalates to the full suite and names the path, because returning "no tests" there is a false all-clear of the same class as a gate whose computed scope is narrower than its documented one. Non-source paths are exempted by an explicit per-path rule reported as `ignored_non_source: [{path, rule}]`, so the exemption is auditable rather than an opaque allowlist; `--non-source GLOB` lets a caller widen it deliberately. `matched_group_ids` is kept distinct from `selected_group_ids` so a reader can see which groups entered via a file match and which via a boundary. **Stdlib-only for a specific reason** — it is invoked as a bare `python3` from agent prose, so a third-party import would make it a finding of `check_gate_liveness.py`'s own `ambient-import` check; that is why it hand-parses the schema's YAML subset (via the private sibling `_topology_yaml.py`) and **fails loudly on any construct it does not recognize**, since a parser that silently dropped a group would make the tool under-select. `--changed`, `--changed-from`, `--tier`, `--json`, `--topology`, `--repo-root`. Canaries in `scripts/test_resolve_test_scope.py` (93 tests) cover escalation, one-hop-excludes-the-second-hop, parallel-unsafe separation, and fail-loud parsing; fixture topologies in `tests/fixtures/test_topology/`
- `check_agent_shared_blocks.py` — Holds the prose blocks replicated inline across agent definitions byte-identical to a single source of truth. The task-slug scoping paragraph is inlined in 15 agents and **cannot be extracted** (agents inherit no rules or CLAUDE.md content, and plugin-distributed agents cannot read runtime reference files), and it had already forked into four tails. The canonical text is a module constant here rather than a `claude/canonical-blocks/` entry on purpose: every mechanism in that directory keys off the `BLOCKS` registry rather than a directory listing, so an unregistered file there is a stowaway no mechanism can see — and this is a mid-paragraph *sentence* with per-agent lead-ins, not a fenced section. Carriers are **detected, not enumerated** (a hardcoded list is itself a drift vector); the comparison unit is the canonical sentence anchored at ``The **task slug**``, so per-agent lead-in clauses and trailing context are not drift, while a tell without the anchor is `anchor-missing`. `--print-canonical` emits the exact bytes. Stdlib-only. Wired as pre-commit `agent-shared-blocks` (Block B6), with the script itself in the hook's `files:` pattern so editing the source of truth re-runs the comparison. Canaries for all three historical tails in `scripts/test_check_agent_shared_blocks.py`

Tests: `scripts/test_upgrade_project_pins.py`

## Conventions

- Shell scripts (bash), `set -euo pipefail` (except `praxion-parallel` which uses `set -eo pipefail` because it intentionally tolerates unset optional vars)
- Python scripts: stdlib-only when possible. `praxion-parallel-ui` follows this — `http.server`, `secrets`, `subprocess`, `webbrowser`, no third-party deps.
- Each script is self-contained with usage documentation in header comments
- `chronograph-ctl` and `phoenix-ctl` are development/operations tools — in production, MCP servers run via plugin.json

## Installer Filter

`install_claude.sh` links scripts under `~/.local/bin/` only when they are `-f && -x` AND do not match `merge_driver_*` or `git-*-hook.sh`. User-facing tools must be executable (`chmod +x`); merge drivers and git hooks are invoked by git, not by PATH, so they are intentionally skipped. Orphaned symlinks (from renamed/removed scripts) are cleaned on upgrade by `clean_stale_symlinks`. See dec-042.

Asset directories (`scripts/praxion_parallel_ui_assets/`) are not executable files and are not linked into `~/.local/bin/`. The `praxion-parallel-ui` script resolves its assets via `realpath(__file__)` so the symlinked launcher finds the original asset directory through the symlink chain — same pattern as `praxion-claude-dev` and `praxion-hackathon`.

## Wired into Onboarding

The `/onboard-project` command installs several of these scripts as git hooks and merge drivers in user projects. When changing any of them, verify the onboarding flow's expectations still hold:

- `git-finalize-hook.sh` + `finalize_chain.sh` — symlinked into `.git/hooks/{post-merge,post-commit,post-checkout}` by `/onboard-project` Phase 4 (state-driven finalize chain — every path landing drafts on main eventually triggers one of the three hooks)
- Praxion's own commit gate lives in `.pre-commit-config.yaml` (the `pre-commit` framework): the six author gates — shipped-artifact isolation, canonical-block sync, diagram regen, AaC golden-rule, rules-manifest drift, HTML authorship boundary — run as `repo: local` hooks alongside ruff + gitleaks, activated by `install_claude.sh` via `pre-commit install`. User projects instead get a *tailored* inline hook written by `/onboard-project` Phase 4 that runs only `check_id_citation_discipline.py` — Praxion's shipped-artifact concern doesn't apply downstream
- `merge_driver_observations.py` — registered via `git config merge.observations-jsonl.driver` by `/onboard-project` Phase 3 (alongside the `.gitattributes` entry). The retired `merge_driver_memory.py` (in-house memory subsystem) is gone; onboarding now *removes* any leftover `memory-json` driver — see Phase 3 cross-version cleanup
- `check_id_citation_discipline.py` — invoked by the user-project pre-commit hook installed in Phase 4
- `finalize_adrs.py`, `finalize_tech_debt_ledger.py`, `reconcile_ai_state.py`, `check_squash_safety.py` — invoked by the finalize hook chain (composition varies per trigger; see `finalize_chain.sh`)

Path or interface changes to these scripts must update `/onboard-project` Phase 3 (`git config` driver line) and Phase 4 (inline pre-commit hook body) to match.

`upgrade_project_pins.sh` (wrapped by `/upgrade-project`) re-points the same hook symlinks and merge driver after a plugin version bump — it is the focused, gate-free upgrade path that re-runs only the version-pinned subset of Phases 3/4/8f. Its re-point target (`${PLUGIN_INSTALL_PATH}/scripts/git-finalize-hook.sh`), driver line (`merge.observations-jsonl.driver`), and expected-driver set (`observations-jsonl`) **must stay in lock-step** with onboard's Phase 4/8f. When you change either side, change both — `upgrade_project_pins.sh` is the deterministic mirror of onboard's version-aware predicates. **P3b adds a second lock-step (the caller-reconcile op):** the script's Praxion-hub `uses:` match pattern and its `cross-model-review.yml.tmpl` render must track onboard §8e.8's ci-autofix + cross-model install; the hub SHA is resolved in the `/upgrade-project` command layer and passed as `--hub-sha` (mirroring 8e.8's install-time resolution — the reconciler never fetches). Keep the command-layer resolution and the script's rewrite/render in step.
