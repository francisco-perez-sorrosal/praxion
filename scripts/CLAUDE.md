# Scripts

Utility and operational scripts for the Praxion ecosystem.

## Available Scripts

- `praxion-hackathon` — Launch Claude Code in hackathon mode with launch-time context trimming: passes `--disable-slash-commands` (~5–8K skill tokens trimmed), `--effort low`, `--append-system-prompt` (from `.claude/hackathon-directive.md`), and `--settings` (`.claude/hackathon-settings.json`). Mode activation (env var, CLAUDE.md block, rules preset) is project-scoped and works on any launch; this wrapper adds the skill-surface trim layer that `settings.json` cannot. Use `scripts/praxion-hackathon --resume` to re-attach. Set `PRAXION_HACKATHON_NO_PS1=1` to suppress the `[hackathon]` PS1 prefix. Dogfooding copy — template source at `claude/aac-templates/praxion-hackathon.sh.tmpl`
- `praxion-claude-dev` — Launch Claude Code with the Praxion working tree as the plugin source (wraps `claude --plugin-dir`). Passes `--dangerously-skip-permissions` by default; set `PRAXION_DEV_SAFE=1` to keep prompts. See [Session-scoped local testing](../README_DEV.md#session-scoped-local-testing)
- `praxion-parallel` — Launch N parallel Claude Code sessions in Warp (default) or iTerm2, each visually distinguished by per-tab color and title, each in its own git worktree via `claude --worktree`. Supports `--worktrees new|existing|none`, per-session `--names`, `--tasks`, and `--append-system-prompts` (pipe-separated, for recipe-style role assignment); `-y/--yolo` for `--dangerously-skip-permissions`. Warp backend writes an ephemeral Launch Configuration under `~/.warp/launch_configurations/` and invokes `open warp://launch/<name>`; iTerm2 backend drives `osascript` and sends OSC-6 escape sequences for per-tab color. `--dry-run` prints the spawn plan. `--ui [PROJECT]` hands off to `praxion-parallel-ui` (the ephemeral web launcher). Replaces the legacy tmux-based `ccwt`
- `praxion-parallel-ui` — Ephemeral localhost launcher for `praxion-parallel`. Stdlib-only Python (`http.server`), binds `127.0.0.1` on a kernel-chosen port, prints a single-use 32-byte URL token, opens the user's default browser. The single-page UI composes a multi-session launch — project, terminal, worktree mode, per-session name/task/system-prompt/`/color` — submits to the bash engine via `POST /api/launch`, and the server self-terminates after the first successful launch (or 10 min idle). User recipes persist at `~/.config/praxion-parallel/recipes.json`; project-local recipes at `<project>/.praxion/recipes.json` (precedence `builtin < user < project`); six built-in templates (`solo-work`, `implement-and-test`, `team-lead`, `compare-implementations`, `feature-fan-out`, `overnight-autonomous`) ship under `scripts/praxion_parallel_ui_assets/`. **Praxion-aware mode** activates automatically on projects with `.ai-state/`: the per-session `agent` field replaces explicit `system_prompt` (auto-derives "Operate as the Praxion @<agent>..." at submit time), worktree name auto-fills from the agent, and the agents dropdown is populated from `<project>/agents/`, the marketplace cache, or a hardcoded fallback. Inspired by named-preset patterns in community tools (Codeman, Nimbalyst)
- `chronograph-ctl` — Development helper for the Task Chronograph MCP server (start/stop/restart/status/logs from source)
- `phoenix-ctl` — Manage the Phoenix observability daemon (install/start/stop/restart/status/uninstall via launchd)
- `reconcile_ai_state.py` — Post-merge reconciliation for `.ai-state/` artifacts: observations.jsonl dedup, ADR renumbering, index regeneration. Called by `/merge-worktree` — `--target-mount <mount>` reconciles a sidecar state mount at merge-back instead (ARCH_WT_RULING.md § 8), and the project-side call is a no-op on a `SidecarOwned` project since the project repository does not own `.ai-state/`.
- `reconcile_pipeline_state.py` — Pipeline step-completion reconciler for truncation recovery. Side-effect-free reader: classifies every `WIP.md` step against ground truth (`git diff` over each step's attributable `Files:` + that step's own `TEST_RESULTS.md` runs is the arbiter -- a file declared by several steps is evidence only for its earliest declarer, and the WIP claim and `Result:` grammar come from the private sibling `_step_schema.py`; `.ai-state/observations.jsonl` WAL is a localization hint) into per-step verdicts (`verified-complete` / `mismatch` / `partial@<pt>` / `in-flight` / `unknown` / `pending` / `blocked` / `attempts-exhausted`), emitting JSON on stdout (exit 0 clean / 1 recovery-needed / 2 unknown, blocked or attempts-exhausted, a human decides / 3 error); each verdict names `decided_by` (`check` / `fallback` / `none`), plus `outcome_source` when a check decided and `attempt` when `WIP.md` records a count. `attempts-exhausted` is a step that is not verified complete and has used its fresh attempts (the `Attempts:` count in `WIP.md`): it carries the verdict it replaced and a replan request, and is never auto-resumed. The verdict state machine itself lives in the sibling `_step_verdict.py`. `blocked` is an otherwise-done step tagged `mutation: on` whose latest green run carries no `Mutation:` line, or a refusal other than `not-flat-layout`: it blocks the step, is never auto-marked or resumed, and clears only when the sensor is restored and re-run or the plan drops the tag with a recorded reason; a tag the fail-closed grammar in `_step_schema.py` cannot read also blocks. Ground truth — not the checkbox — drives `verified-complete`, so a step whose files are all changed but still `- [ ]` is caught (the died-before-checkbox case); ambiguous correlation degrades to `unknown`, never a guessed verdict. Resolves repo root from `--repo-root` / `git rev-parse`, never `__file__`; refuses plugin-cache paths. Driven by `/resume-pipeline`. Tests + gate-liveness canary in `scripts/test_reconcile_pipeline_state.py`
- `_loop_fields.py` — The grammar of the two fields a plan or `WIP.md` declares for the step loop, one parser each. **`Check:`** (`parse_check_field`, `parse_step_checks`): a backticked command plus `pass`/`fail`/`skip`/`pending` expectations, each with `=` or `>=`, in any order; the normative grammar is the module docstring, and a line that breaks it is an `UnreadableCheck` naming why, never a guessed check. `evaluate_check` judges a check against the step's **own** latest recorded `Result:` line only (never another step's, never a file-wide fallback) and returns `Met`, `Unmet` or `NoResult`; it is the one reader of `pending=` and never runs the command. **`Attempts:`** (`parse_attempts`, `ATTEMPT_CAP`): the self-naming `- Attempts: Step <id> count=<n>[ [BLOCKED] replan: <text>]` sub-bullet the orchestrator writes ahead of each fresh spawn; the highest count per step wins whatever the line order, a line that breaks the grammar is reported as unreadable for its step (one that names no step is listed apart as unnamed), and a line inside a code fence declares nothing. `latest_result` is the one reader of a step's latest `Result:` line, shared by `evaluate_check` and the iteration ledger, so a later `Result: none` is never read as an earlier count line. Stdlib-only and 3.9-safe, read by the reconciler and by `_step_verdict.py`. Tests: `scripts/test_loop_fields.py`, `scripts/test_loop_attempts.py`
- `_step_verdict.py` — The reconciler's pure verdict core: `classify_step(evidence, declared_check, attempts)` returns the verdict dict from its arguments alone (no file read, no command, no clock; the reconciler gathers the evidence). Policy in order: a step that declares a check is decided by the check against its recorded result (a met check completes it unless a mutation-reading blocker applies; a claim of completion never outranks an unmet or missing result; an unreadable check is surfaced to a human); a step with no check is decided by its changed `Files:` and test status; a step at `ATTEMPT_CAP` that is not verified complete becomes `attempts-exhausted` with the replaced verdict kept in its evidence, and an unreadable `Attempts:` line routes the step to `unknown` the same way, because a count that cannot be read cannot be trusted to be below the cap. `make_verdict` is the only place a verdict dict is built, so the stamps (`decided_by`, `outcome_source`, `attempt`) follow from its inputs. Exports `VERDICT_WORDS` and `HUMAN_VERDICTS`, the one vocabulary the reconciler and the ledger share. Stdlib-only and 3.9-safe. Tests: `scripts/test_step_verdict.py`
- `iteration_ledger.py` — The iteration ledger's only reader and writer: `.ai-work/<slug>/ITERATION_LEDGER.jsonl`, one append-only JSON object per implementer return (step, attempt, agent id, reconciler verdict with `decided_by`, the step's `Result:` line, the commit sha or an explicit JSON `null`, and the stop reason: `completed`, `turn-cap`, `blocked` or `no-marker`). The module docstring is the normative shape and every invariant is enforced at the one line parser, so a record that reads back is valid: an absent `commit` key is a finding (never read as null), unknown extra keys are ignored, and a `v` other than 1 is a finding. A goal-mode record may add `cost_usd` (a number of at least 0) and `progress_lines` (an integer of at least 0): parsed when present, rendered only when not `None` after the existing keys, and both need a `request`, so every other record's line stays byte-identical. `read_ledger` returns the records plus a `LedgerFinding(position, reason)` for each line that breaks the shape, located by append position and never skipped or guessed; an absent or empty ledger reads as no history. `append_record` stamps the append time (UTC to the minute), proves the rendered line reads back, and only then writes it as one append-mode write, so an invalid record never touches the file. **Command line:** `append <slug> --step <id> --attempt <n> --agent-id <id> --stop-reason <reason> (--commit <sha> \| --no-commit) [--base-ref REF]` derives `verdict` and `decided_by` from a `reconcile()` call and `test_result` from the step's latest `Result:` line in its own `TEST_RESULTS.md` block (a declared `Result: none` when it recorded none), so the orchestrator never types them; `read <slug> [--json]` prints the records and findings (exit 0 clean / 1 findings / 2 input error). The repo root comes from `--repo-root` or git, never from `__file__`, and a plugin-cache root is refused; `--worktree-root` locates `.ai-work/`. The reconciler is imported only when `append` runs, so the library half stays importable from `scripts/` alone. Stdlib-only and 3.9-safe; **executable**, so the installer puts it on `PATH`. Tests: `scripts/test_iteration_ledger.py` (shape, reader, writer, identity), `scripts/test_iteration_ledger_cli.py` (command line, executable bit), `scripts/test_iteration_ledger_goal_keys.py` (goal keys)
- `spawn_count.py` — Per-pipeline spawn/resume tally for the Standard/Full spawn budget. Stdlib-only reader of the observations log of every checkout `git worktree list` reports (every numbered archive, deduplicated by whole-row identity, time-ordered): spawns counted by the `Task slug:` their prompt states (the `Agent` result row's `task_slug`, else the agent's own transcript prompt; rows written before attribution count by `project`; a spawn no rule attributes joins the pending pool and is listed under the conditional `unattributed` key); an `agent_id`'s first start is a spawn, a later start a resume, and a resume into a context at or above the heavy-context threshold counts as a spawn. `--slug`, `--budget`, `--json`; exit 0 counted / 1 over budget / 2 withheld (no or unreadable log, slug unseen, plugin-cache root) — a withheld count is never reported as zero. Read by the orchestrator before each spawn (`skills/software-planning/references/coordination-details.md § Spawn Budget`). An agent the task's iteration ledger records under a request id is an `iterations` entry, not a charged spawn. Tests in `scripts/test_spawn_count.py`
- `step_loop.py` — The step-loop driver: says which agent the orchestrator starts next. Five verbs, `next`, `record`, the read-only `status` (each printing one JSON envelope), `goal` (scaffolds a one-step goal plan, run from the repository root) and `run` (the terminal form of a goal loop: `drive` over one fresh headless `claude -p` worker per iteration, one stderr line per iteration, every printed command carrying the base and roots it was given; refuses a plan with no goal step or a missing deny rule before any worker); exit 0 spawn or complete / 1 driver failure / 2 a human decides / 3 iteration budget used up / 4 caller error. Keeps no state of its own: every call re-derives from the plan, `WIP.md`, `ITERATION_LEDGER.jsonl`, `TEST_RESULTS.md` and git, and commits a verified step by explicit path. Procedure: `skills/step-loop/SKILL.md`. Goal mode: `skills/ralph-lite/SKILL.md`. Modules behind it: `_goal_record.py` (judges a goal iteration), `_goal_run.py` (what `run` checks before every worker starts: the deny rules, the inherited pre-approvals, the tree outside the goal's paths and the goal step's block; the start marker beside each worker file; and the line it prints per iteration), `_goal_scaffold.py` (scaffolds a goal plan), `_goal_worker.py` (starts the headless worker under a write allow-list of the goal's paths and only its own pre-approvals), `_step_loop_action.py` (pure decision: spawn, complete, stop), `_step_loop_cli.py` (envelopes and exit codes), `_step_loop_files.py` (file and transcript adapters), `_step_loop_gate.py` (pytest output reading), `_step_loop_io.py` (git and command adapters), `_step_loop_record_gate.py` (test run, result block), `_step_loop_record.py` (takes back an agent's return), `_step_loop_render.py` (request ids, prompt text), `_step_loop_review.py` (light-review state), `_step_loop_settle.py` (what record leaves behind), `_step_loop_state.py` (per-step series state); the plan reader is `_plan_steps.py`

- `adr_health.py` — ADR **reference-decay classifier**. For every `affected_files` entry that no longer resolves, classifies *why* into seven causes — `placeholder-shape`, `out-of-repo`, `lazy-artifact`, `renamed`, `removed-by-self`, `removed-by-later`, `vanished` — because only the last means "retire" and a naive existence check flags every "remove X" decision as stale, inverting the truth on the most load-bearing records. `removed-by-later` is the highest-value output: it reconstructs supersession edges that exist in reality but were never recorded. Reuses `validate_adr_references.parse_affected_files` rather than re-implementing it; builds deletion and rename indexes with **two** git calls total (per-path `git log` would be ~1,400 subprocesses). **Advisory by construction** — emits candidates, never edits an ADR or a `status`, exit 0 always. When git history or the lifecycle table is unavailable, the dependent classes are **withheld with a named reason** rather than defaulted to `vanished` — including `vanished` itself, which is a dependent class (it means every repair class was *tried* and none matched, true only when every oracle answered), so an unavailable oracle yields `unclassified`/no-disposition rather than a retirement candidate. The lifecycle table resolves from the project root **first and the plugin's own tree second**: it is plugin reference data that no onboarding phase writes into a managed project, so a project-root-only lookup left the oracle permanently unavailable everywhere except this repository. Decisions at a terminal `status` are excluded (their references are history, not a live index) and counted in `skipped_terminal`; `retired` ones are probed in the reverse direction, so a retired decision whose paths resolve again surfaces in `reopen_candidates` — retirement stays reversible instead of becoming a one-way delete. Also reports `category_mix` (corpus + recent-window counts and the recent `architectural` share) — a **measurement, not a gate**: whether a decision changed the component inventory is not derivable from frontmatter, so the `architectural` test cannot be checked mechanically, but its effect can be watched against the adoption baseline. Counts terminal decisions too, since categorisation is an authoring question and retiring a record must not flatter the ratio. Consumed by the sentinel's DH dimension (`--json`); also runnable standalone (`--class <name>` filters). **Installed on `PATH` by `install_claude.sh`** so the shipped [`/decisions`](../commands/decisions.md) command can call it in user projects — the executable bit is what the installer filters on, so removing it silently un-ships the command's only data source. Sibling imports resolve through the symlink to the real `scripts/` directory, so `_repo_root.py` and `validate_adr_references.py` need no link of their own. Tests + per-class canaries in `scripts/test_adr_health.py`
- `ledger_snapshot.py` / `ledger_delta.py` / `ledger_delta_signals.py` — State-snapshot **reader** for the tech-debt ledger: a ledger row is a claim about the project on the day it was filed, and this reads the *current* state once — the ledger pair (parsed into typed rows, `dedup_key` facts via `state_ledger_schema`, never re-derived), the ADR corpus (edges via `query_adrs`'s frontmatter primitives), git history (`adr_health`'s rename and deletion indexes plus one commit index; never a per-row git call) — into an immutable `StateSnapshot`. `ledger_delta.py` holds the schema (rows, stamps, windows, signals) and `ledger_delta_signals.py` the pure core over it: `row_delta(snapshot, row)` computes, with no I/O, the row's signals (`location-decay`, `citation-decay` for repo paths and `path:line` cites in notes that no longer resolve, with the rename target when known, `decision-drift`, `goal-link-unresolved`, `cited-by-commit`, `possible-duplicate`, `self-amended`) and its context. **File overlap with an ADR is context, never a signal** — it links half the live ledger, live rows included. Oracle-dependent classes are **withheld with a named reason** when git, the ADR corpus or the lifecycle table cannot answer, so a missing index is never read as a vanished file. Also owns the triage-stamp grammar (`parse_stamp`, a smart constructor that rejects a `discarded` stamp carrying no checkable anchor). Stdlib-only. Tests in `scripts/test_ledger_snapshot.py` over a frozen ledger fixture (`scripts/test_fixtures/ledger_triage/`)
- `ledger_health.py` — Tech-debt ledger triage **probe** over `ledger_snapshot.py`: a row is a candidate iff its delta carries a signal, ranked by the `CLASS_POLICY` tier table (strong when the state contradicts the row, medium when the row was only amended in place); age, churn and ADR overlap ride along as context. Default output is a text summary; `--digest` emits a `ledger-triage-digest/1` JSON envelope for a judge — the row verbatim, key facts (`rekeys_on_notes_edit`), evidence and context kept apart, withheld classes with reasons. `--index` emits the same envelope with the selected ids in rank order instead of the row bodies (`ledger-triage-index/1`, about 1.5 KB where the whole ledger's digest runs to hundreds): `/triage-debt` fans out from it, and each judge fetches its own batch with `--digest --ids`. `--json` emits the sentinel TD07 family envelope. `--all`, `--ids`, `--class`, `--repo-root`. `--row td-NNN --stamp-file <path>` is the `/triage-debt` apply step's gate, and the stamp arrives in a file, never as a shell argument — it quotes repository text, and a quote closed early on a shell line runs the backtick span after it. The stamp (one line, no `|`) must parse, must read back as the row's latest judgment once appended to its `notes` (`--notes-file <path>` supplies a realign's rewritten notes, which must be one line with no `|` and keep every segment and earlier stamp byte for byte), and every anchor must resolve at `HEAD` — its own `@anchor` and every cited sha an ancestor of `HEAD` (an object on an unmerged branch is not history), every cited path tracked in the `HEAD` tree (a gitignored file on disk is not evidence) and every cited line inside its file, a finalized decision, a ledger row other than itself (a row tombstoned earlier in the same run still counts), an active merge survivor. A `realigned` stamp's text is the premise it replaced, so only its own `@anchor` is resolved. `--location '<cell>'` gives a realign's new location, each path tracked at `HEAD` and each cited line inside its file — exit 0 `ok`, exit 1 one `refused:` line per problem. **Advisory by construction** — writes nothing, exit 0 whatever it finds, exit 2 only on an unreadable ledger, stamp or notes file, or a plugin-cache root. Executable, so the installer puts it on `PATH` (as it does `check_state_ledgers.py`, which the command runs after applying). Tests in `scripts/test_ledger_health.py`
- `check_architecture_projection.py` — Reconciles the LikeC4 model against `.ai-state/DESIGN.md` §3a: every structural component must have a row and every row must name an element. The binding is **explicit** — each row carries the element id in an `Element` column — because row and element titles legitimately differ ("Agent runtime / Pipeline" vs "Agent Pipeline"), so title matching would both miss real drift and invent false drift on a rename; carrying the id in the doc also puts the binding in front of a human reader. *Structural* means no child component: the four layer containers get no row, while a component whose only children are agents or documents does. Four finding kinds (`element-without-row`, `row-without-element`, `unknown-element`, `not-structural`); resolving one is a judgment about which side is right, so it never edits either. A **second reconciliation covers the published half**: §4's canonical-block rows against the `BLOCKS` registry in `sync_canonical_blocks.py` (`block-without-row` / `row-without-block`) — those blocks are installed into every managed project's own `CLAUDE.md`, so an undocumented one costs N repositories rather than this one. The registry is **parsed from `repo_root`, not imported from `sys.path`**, so `--repo-root` relocates both authorities instead of reconciling one tree's design doc against another tree's registry, and the checker never executes code from the tree it inspects; a non-literal registry key withholds rather than part-reading. An unreadable registry **withholds** that half rather than reporting that nothing ships. Stdlib-only, `--json`, `--repo-root`; exit 1 on findings, so it doubles as the `architecture-projection` pre-commit gate (which must stay wired to `claude/canonical-blocks/` as well as the model and DESIGN.md, since adding a block touches neither of the latter). Also consumed by sentinel AC13. `classify()` additionally covers AC04 (every inline `dec-NNN` in `.ai-state/DESIGN.md`/`docs/architecture.md` resolves to a finalized ADR) and AC05 (`docs/architecture.md` exists and is non-empty); both ride AC13's own substrate gate and always report `severity: "warn"` -- advisory, never exit-code-bearing, so the pre-commit gate cannot redden on them. Tests + canaries for all four kinds plus AC04/AC05 in `scripts/test_check_architecture_projection.py`
- `measure_token_budget.py` — The always-loaded token budget, **measured**. Counts real tokens via the Anthropic `count_tokens` endpoint when `ANTHROPIC_API_KEY` is set; without one it falls back to a **labelled** `bytes / 3.6` estimate and says so, because reporting an estimate as a measurement is how a folk divisor became load-bearing in the first place. ## Conventions

- Shell scripts (bash), `set -euo pipefail` (except `praxion-parallel` which uses `set -eo pipefail` because it intentionally tolerates unset optional vars)
- Python scripts: stdlib-only when possible. `praxion-parallel-ui` follows this — `http.server`, `secrets`, `subprocess`, `webbrowser`, no third-party deps.
- Each script is self-contained with usage documentation in header comments
- `chronograph-ctl` and `phoenix-ctl` are development/operations tools — in production, MCP servers run via plugin.json

## Installer Filter

`install_claude.sh` links scripts under `~/.local/bin/` only when they are `-f && -x` AND do not match `merge_driver_*` or `git-*-hook.sh`. User-facing tools must be executable (`chmod +x`); merge drivers and git hooks are invoked by git, not by PATH, so they are intentionally skipped. Orphaned symlinks (from renamed/removed scripts) are cleaned on upgrade by `clean_stale_symlinks`. See dec-042.

Asset directories (`scripts/praxion_parallel_ui_assets/`) are not executable files and are not linked into `~/.local/bin/`. The `praxion-parallel-ui` script resolves its assets via `realpath(__file__)` so the symlinked launcher finds the original asset directory through the symlink chain — same pattern as `praxion-claude-dev` and `praxion-hackathon`.

- `git-finalize-hook.sh` + `finalize_chain.sh` — symlinked into `.git/hooks/{post-merge,post-commit,post-checkout,post-rewrite}` by `phases-core.md` §Phase 4 (state-driven finalize chain — every path landing drafts on main eventually triggers one of the finalize hooks; worktree-log merge-in from post-merge, from post-commit for a merge finished by a commit, and from post-rewrite for a rebase)
- Praxion's own commit gate lives in `.pre-commit-config.yaml` (the `pre-commit` framework): the author gates — shipped-artifact isolation, id-citation discipline, canonical-block sync, diagram regen, AaC golden-rule, rules-manifest drift, HTML authorship boundary — run as `repo: local` hooks alongside ruff + gitleaks, activated by `install_claude.sh` via `pre-commit install`. User projects instead get a *tailored* inline hook written by `phases-core.md` §Phase 4 that runs only `check_id_citation_discipline.py` — Praxion's shipped-artifact concern doesn't apply downstream
- `merge_driver_observations.py` — registered via `git config merge.observations-jsonl.driver` by `phases-core.md` §Phase 3 (alongside the `.gitattributes` entry, which since dec-377 / td-182 targets the committed `observations_summary.jsonl` rollup — merged by `session_id`; the driver dispatches on row shape so a sidecar's tracked raw WAL still gets the composite-key merge). The retired `merge_driver_memory.py` (in-house memory subsystem) is gone; onboarding now *removes* any leftover `memory-json` driver — see §Phase 3 cross-version cleanup
- `check_id_citation_discipline.py` — invoked by the user-project pre-commit hook installed in `phases-core.md` §Phase 4
- `finalize_adrs.py`, `finalize_tech_debt_ledger.py`, `reconcile_ai_state.py`, `check_squash_safety.py` — invoked by the finalize hook chain (composition varies per trigger; see `finalize_chain.sh`)

Path or interface changes to these scripts must update `phases-core.md` §Phase 3 (`git config` driver line) and §Phase 4 (inline pre-commit hook body) to match.
