Build the representation first, from `SYSTEMS_PLAN.md § Data Structures` items 1 and 2: the sum type `Check` | `UnreadableCheck(reason, line)` with every invariant enforced in the smart constructor `parse_check_field` (both `pass` and `fail` present; each key at most once; command non-empty and free of backticks; no unknown key and no trailing token; a block holding two `Check:` lines is `UnreadableCheck("declared twice")`); `parse_step_checks(plan_text) -> dict[step, Check | UnreadableCheck]` over `_step_schema.split_step_blocks` (a step with no line has no entry); the sum type `CheckOutcome` = `Met` | `Unmet(unmet, observed)` | `NoResult(reason)` with `UnmetExpectation` rendering as `pending=: expected =0, observed 2`; `evaluate_check(check, step, test_results_text)` reading only the latest `Counts` line in that step's own block (a result recorded for another step, a file-wide fallback, `Result: none`, a malformed line or no line is never `Met`), the sole reader of `pending=` (read from the raw text of that `Result:` line; absent means 0); and a module constant holding the one-line grammar the prose sites will quote. ### Step 6: Check-first verdict with the attempt cap (`_step_verdict.py`) [depends-on: 3, 4, 5]

**Assignee**: implementer
**Implementation**: In `scripts/_step_verdict.py` build the policy from `SYSTEMS_PLAN.md § Data Structures` item 4 and Decisions D1 and D3. `classify_step(evidence, check_outcome, attempts)` dispatches to a fallback path (the moved logic, split so no function exceeds 50 lines), a check path, then the cap override. Check path: a readable declared check decides; `Met` gives `verified-complete` unless an existing completion blocker applies (a `mutation: on` step with no usable reading stays `blocked`); `Unmet` or `NoResult` never gives `verified-complete`; a claimed step (ticked or `[COMPLETE]`) is `mismatch` with evidence `WIP=[COMPLETE] but check unmet: <key>=: expected <op><n>, observed <m>[; ...]` or `... but no Result: recorded for <step>`; an unclaimed step with changes keeps the existing partial / in-flight logic; an `UnreadableCheck` gives `unknown` with evidence naming the check. Cap override: `attempt >= ATTEMPT_CAP` and a verdict other than `verified-complete` becomes `attempts-exhausted`, whose evidence carries the replan request (when recorded) and the underlying verdict and evidence; this covers `in-flight`, `partial`, `mismatch`, `unknown` and `pending`. `make_verdict` is the only constructor of the verdict dict and enforces the stamping invariants: `decided_by` always (`check` when the step declares a check, readable or not; `fallback` when it declares none; `none` exactly when the verdict before any cap override is `pending`), `outcome_source` only when a check outcome was read (always `recorded` here), `attempt` only when recorded; optional keys are omitted, never null. Export `HUMAN_VERDICTS = ("unknown", "blocked", "attempts-exhausted")` and one constant listing every verdict word. Tests in new `scripts/test_step_verdict.py`: a parity table over every branch of the moved fallback logic, the check-first table (met, each unmet key, no result, unreadable, blocker precedence), the golden bad case (ticked and unmet is never `verified-complete`), the cap over every non-complete verdict with `verified-complete` untouched, the `make_verdict` invariants, and that a legacy-shaped call yields a verdict dict equal to the moved logic's plus exactly `decided_by`.
