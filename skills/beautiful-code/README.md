# beautiful-code

The eight dimensions of beautiful code — Storytelling, Simplicity, Clarity of intent, Expressiveness, Purity, Sustainability, Durability, Creativity — as named, reviewable qualities. Operationalizes `CLAUDE.md§Structural Beauty`.

- **What it is** — an *index plus gap-filler*: each dimension names its canonical home in Praxion's existing conventions (`coding-style` sections, behavioral contract, sibling skills) and adds only the depth nothing else carries — the practitioner canon, the cross-dimension tension resolutions, and the judgment-layer review checklist.
- **Key reconciliations** — creativity vs "readability over cleverness" (clever line-level tricks stay banned; insightful design-level reframing is licensed with a documented premise); boy-scout rule vs Stay Surgical (bounded, in-diff cleanup only); durability's compatibility ratchet vs refactoring (the ratchet binds public consumed surfaces; internals stay free); purity as a continuum, not a gate.
- **Pipeline integration** — dimension conventions live in path-scoped `coding-style` sections the verifier's Phase 5 derives from; [references/beauty-review-checklist.md](references/beauty-review-checklist.md) carries the judgment layer for milestone reviews; `.ai-state/principles.yaml` can thread the dimensions into step acceptance criteria and verifier Phase 4.5 gating (Praxion's own instance does).
